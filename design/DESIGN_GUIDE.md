# 투자 샘터 — 디자인 및 페이지 확장 가이드

기준일: 2026-09-08 · 문서 버전: 1.15

이 문서는 새 페이지와 메뉴를 만들 때 읽는 공통 기준이다. 현재 구현을 기록한 부분과 앞으로 적용해야 할 규칙을 구분한다. 최초 기획 문서 `investment-spring-design.md`의 고정 사례 수·제안 단계 설명은 현재 구현의 기준으로 사용하지 않는다.

## 1. 제품과 화면의 역할

제품 이름은 **투자 아이디어 샘터**, 헤더 로고는 **투자 샘터**다. 목적은 투자 사례와 경제 변화의 경로를 찾아 읽고, 새로운 조사 질문을 만드는 개인 리서치 공간이다.

기본 접속 주소는 https://investment-spring.vercel.app 이다. 아래 `dist/` 경로는 로컬 산출물이며, 웹에서는 `dist/`를 제외한 동일 경로를 사용한다. 사례 탐색 고정 주소는 https://investment-spring.vercel.app/#cases 이다.

| 화면 | 사용자 목적 | 주소 |
|---|---|---|
| 홈 | 검색하거나 작업을 고른다 | `dist/index.html#home` |
| 사례 탐색 | 종목·이슈·테마·패턴으로 사례를 찾는다 | `dist/index.html#cases` |
| 통합 검색 | 사례와 인과지도를 함께 찾는다 | `dist/index.html#search?q=…` |
| 거시 경로 목록 | 살펴볼 전달 경로를 고른다 | `dist/index.html#macro` |
| 거시 인과지도 상세 | 조건·시차·반대 경로를 살펴본다 | `dist/macro.html` |
| 통합 인과망·검증실 | 모든 사례와 거시 경로를 연결하고 선행 예측력·판정 기준을 재검토한다 | `dist/causal-network.html` |
| 일반 사례 상세 | 주가·상대강도·수급과 사건을 읽는다 | `dist/<코드>_dashboard.html` |
| 별도 검증 상세 | 특정 질문에 맞는 분석을 읽는다 | 예: `dist/010950_brent.html` |

| 지수 레이더 | 지수의 현재 구성과 시가총액 기준 비중, 출처·품질 상태를 확인한다 | `dist/index-radar.html` |
| 지수 레이더 History | 한 정기변경의 공통 조건과 편입 종목별 조건 형성·사후 결과를 비교한다 | `dist/index-radar-history.html` |

### 단계별 확장 화면

`지수 레이더`의 현재 구성 MVP와 첫 History인 `2026년 상반기 KOSPI 200 정기변경`은 구현됐다. History는 리뷰 1건을 기준 페이지로 두고 편입 4종목을 같은 컷오프에서 비교하며, 종목별 영구 앵커를 제공한다. 임의의 두 스냅샷 비교, 완전한 규칙 엔진, 후보 신호, MSCI는 아직 구현되지 않았고 화면에 미리 노출하지 않는다. 다음 단계의 계약은 [`INDEX_RADAR_SPEC.md`](INDEX_RADAR_SPEC.md)를 따른다.

사례 수와 분류별 개수는 데이터로 계산한다. 문구에 '항상 5개' 같은 수를 고정하지 않는다. 사례는 관측된 내용, 인과지도는 조건에 따른 경로라는 차이를 유지한다. 한 사례는 여러 이슈에 연결될 수 있으므로, 사례 수와 이슈 연결 수는 구분해 표시한다.

## 3. 공통 시각 기준

새 페이지의 외부 셸은 통합 홈의 중립색 기준을 따른다. 분석 차트 내부에서는 의미가 정해진 색을 사용한다.

| 역할 | 밝은 모드 | 어두운 모드 |
|---|---|---|
| 전체 배경 `--background` | `#ffffff` | `#09090b` |
| 주요 텍스트 `--foreground` | `#18181b` | `#fafafa` |
| 카드 `--card` | `#ffffff` | `#18181b` |
| 보조 표면 `--muted` | `#f4f4f5` | `#27272a` |
| 보조 텍스트 `--muted-foreground` | `#71717a` | `#a1a1aa` |
| 테두리 `--border` | `#e4e4e7` | `#27272a` |
| 주 버튼 배경 / 글자 | `#18181b` / `#fafafa` | `#fafafa` / `#18181b` |

- 글꼴은 본문·메뉴·버튼·표·SVG 차트까지 `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, "Malgun Gothic", sans-serif`로 통일한다. 숫자는 다른 글꼴 대신 `font-variant-numeric: tabular-nums`를 사용한다.
- 현재 폰트 CDN은 `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css`다. 네트워크가 없으면 대체 폰트가 표시된다. 완전 오프라인 동일 폰트가 필요하면 로컬 폰트 포함을 별도 구현한다.
- 기본 본문 16px, 일반 조작/라벨 14px 이상, 보조 메타 12–13px. 기존 분석 차트의 작은 글자는 현재 예외이며 신규 화면에서 무조건 복제하지 않는다.
- 페이지 제목은 홈 기준 `clamp(28px, 4vw, 42px)`, 줄높이 1.2. 제목은 줄바꿈하고 고정 높이로 자르지 않는다.
- 기본 카드 반경 10px, 입력/버튼 약 8px, 얇은 1px 테두리와 작은 그림자. 강조는 색·굵기·선택 표면으로 표현한다.
- 여백은 4/8/12/16/24/32/48px 계열을 기본으로 하고 현재 셸 패딩 22px은 호환값으로 유지 가능하다.
- 링크는 이동, 버튼은 동작, 체크박스는 표시 선택에 사용한다. hover만으로 기능을 제공하지 않고 키보드 포커스를 보이게 한다.

일반 사례 차트의 의미색은 종목 보라, 비교지수 회색, 상대강도 초록, 회전율 금색, 외국인 파랑, 기관 주황, 개인 분홍이다. 국내 주가 상승 빨강·하락 파랑 표기를 유지하되 범례와 부호를 함께 표시한다. 새 차트 색의 의미가 다르면 반드시 라벨로 구분한다.

## 4. 공통 레이아웃과 모바일

새 화면의 기본 구조는 다음과 같다.

```text
공통 헤더: 투자 샘터 / 주요 메뉴 / 통합 검색
본문: 상위 위치·돌아가기 → 페이지 제목·한 문장 설명
      검색·필터 또는 주요 조작
      결과 목록 또는 분석 차트·표
      출처·기준일·관련 자료
공통 하단 안내
```

- 헤더 최대 너비 1180px, 탐색 본문 1060px, 분석 본문 1180px. 가운데 정렬하며 본문이 화면 너비를 넘지 않게 한다.
- 데스크톱 좌우 여백 22–24px, 모바일 16px. 새 페이지의 Grid 열에는 `minmax(0, 1fr)`, Flex 자식에는 필요 시 `min-width: 0`을 적용한다.
- 카드/컨트롤은 콘텐츠가 길어질 때 세로로 커져야 한다. 긴 한글 이름·영문·코드에도 줄바꿈되도록 한다. 문서 전체에 `overflow-x: hidden`을 넣어 잘림을 감추지 않는다.
- 차트·넓은 표는 자기 컨테이너 안에서만 가로 스크롤한다. 차트 최소 너비를 줄여 축·이벤트를 읽을 수 없게 만들지 않는다.
- 신규 화면은 740px 이하에서 목록 필터와 진입 카드를 1열로 전환한다. 440px 이하에서는 헤더 검색을 전체 너비의 별도 행으로 둔다.
- 기존 화면은 서로 다른 분기점을 쓴다: 포털 740/440px, 일반 사례 KPI 1020/600px 및 헤더 640px, 거시 셸 820px, 에쓰오일 KPI 900px. 실제 수정 대상의 기존 분기점과 충돌 여부를 확인한다.
- 밝은/어두운 모드에서 입력 배경·글자·테두리·선택 상태를 함께 맞춘다. 어두운 모드에 밝은 색을 고정한 카드가 섞이지 않도록 한다.

## 5. 페이지와 메뉴가 늘어날 때의 규칙

아래는 확장 시 적용할 기준이며 현재 사이드바·더보기 메뉴·페이지네이션이 구현됐다는 뜻은 아니다.

| 증가하는 대상 | 확장 방법 |
|---|---|
| 사례·종목·분석 보고서 | 기존 사례 목록에 추가. 개별 종목을 상위 메뉴로 만들지 않음 |
| 이슈·산업·테마 | 분류와 필터로 확장. 탭이 여러 줄을 차지하면 검색 가능한 선택기로 변경 |
| 독립적인 작업 목적 | 새로운 상위 메뉴 후보. 예: 실제 기능이 구현된 아이디어 노트 |
| 상위 메뉴 4개까지 | 헤더에서 주요 동작을 바로 제공. 긴 이름과 1024px 너비도 확인 |
| 5개 이상 또는 실제로 넘침 | 중요 메뉴 + '더보기' 또는 그룹 사이드바로 전환. 글씨를 줄여 끼워 넣지 않음 |
| 모바일 메뉴 증가 | 접을 수 있는 메뉴로 전환. 열림 상태, 닫기, 키보드 포커스와 현재 위치 제공 |
| 사례 수십~수백 건 | 필터·정렬 유지, 필요 시 페이지네이션 도입. 고정 임계치보다 로딩·스크롤 비용으로 판단 |

상위 메뉴는 작업 목적을 담은 짧은 명사로 이름 짓는다. 새 아이디어가 기존 사례/거시 경로로 충분히 표현되면 그 안에 추가한다. 홈 진입 카드가 늘면 `repeat(auto-fit, minmax(min(100%, 280px), 1fr))` 같은 적응형 열을 고려하고 마지막 카드 폭·긴 제목을 확인한다.

새 전역 메뉴 추가 시 헤더가 존재하는 모든 템플릿과 거시 셸을 함께 수정한다. `navigation.json`은 탐색 문구용이며 메뉴 정의가 아니다. 현재 전역 메뉴는 `data/site_navigation.json`과 `tools/site_shell.py`가 생성한다. 템플릿은 `<!--__SITE_NAV__-->` 자리표시자를 사용하고, 포털만 hash 현재 위치를 위해 `data-nav` 속성을 함께 받는다.

네 번째 상위 메뉴는 **`지수 레이더`**다. KOSPI 200부터 시작하되 특정 지수명에 종속되지 않으며, 현재 구성·과거 변경·발표 전 편입 조건을 한 작업 공간에서 다룬다. `현재 구성`과 `History`는 지수 레이더 내부 탭으로 왕복한다. History의 페이지 단위는 종목 하나가 아니라 정기변경 리뷰 하나이며, 같은 기준일·방법론·출처를 공유하는 종목은 한 페이지의 비교표와 종목별 앵커로 구성한다. 현재 구성은 네이버 구성목록과 키움 현재가·유통비율 기반 참고 비중을 제공하고, History는 키움 `ka10059` 관측과 증권사 추정값을 명시적으로 분리한다. 구성목록은 KRX 원본 교차검증 전 보조 출처이며, 공식 KRX 지수 비중과 KRX 지수주식수 기반 비중은 `—`로 표기한다. 후보 예측은 과거 시점 데이터만 사용한 검증을 갖춘 뒤 노출한다. 페이지·데이터·단계별 구현 계약은 [`INDEX_RADAR_SPEC.md`](INDEX_RADAR_SPEC.md)를 따른다.

## 6. 검색·상세 화면의 일관성

- 통합 인과망은 다섯 번째 상위 메뉴를 추가하지 않고 **거시 인과지도 내부 작업**으로 둔다. 거시 목록·상세에서 진입하며 공통 헤더의 거시 메뉴를 현재 위치로 표시한다. `개별 전달 경로`와 `통합 인과망·검증실`은 왕복 링크를 제공한다. 통합 검색은 `인과망·시계열·검증실·알고리즘·네트워크` 검색으로 진입할 수 있다.
- 통합망 외부 셸과 그래프 라벨은 Pretendard 계열이고 밝은/어두운 모드를 모두 지원한다. 740px 이하에서는 그래프와 상세를 세로로 쌓고, 440px 이하에서는 기준 입력을 한 열로 표시한다. 표는 자체 컨테이너에서 가로 스크롤하며 선택기는 화면을 넘지 않는다. `view/node/depth`를 URL에 보존한다.
- 통합망의 보라 화살표는 미검증 인과 가설, 초록 화살표는 시계열 선행 예측, 회색 점선은 방향 없는 소속·관측이다. 노드의 배치·거리·중심성을 영향도 점수로 표현하지 않는다. 미충족 검사를 숨겨도 검증표에는 전체 결과를 볼 수 있어야 한다.
- 공식 판단 기준과 브라우저 초안을 구분한다. 숫자·변경 이유를 검증한 뒤 실행 ID별 localStorage에 이전/이후 값·시각을 보관하고 JSON으로 내보낸다. 초안 변경은 판정 필터 비교이며 재학습·운영 기준 변경이 아니다. 미검증 가설에 임의 점수나 인과 확률을 넣지 않는다. 통계의 계수·유의성·미래 오차·방향 안정성은 별도 표시한다.
- 현재 예외: 기존 거시 상세는 `design/causal-investment-dashboard.html`의 설명을 유지하며 통합망 빌더가 해당 리터럴을 읽는다. 기존 화면의 모든 신뢰도 표기가 통계 검증으로 대체된 것은 아니다. 신규 통합망은 그 정성 신뢰도를 실측 확률로 사용하지 않는다. 3D·자동 재학습·서버 저장·과거 vintage 재현은 구현하지 않았다.

- URL에 검색어·필터·정렬을 보존한다. 기존 `#cases?issue=…&theme=…&pattern=…&q=…&sort=…`와 `#search?q=…` 흐름을 유지한다. 이슈는 쉼표로 연결한 복수 ID(`issue=rights,index-inclusion`)를 허용하며, 선택한 이슈 중 하나와 연결된 사례를 중복 없이 표시한다.
- 사례는 대표 이슈 하나에 고정하지 않는다. 포털 데이터의 `issue_ids`로 복수 이슈를 명시하고, 카드에는 연결된 이슈 태그를 모두 보인다. 사례별 목록은 같은 카드를 한 번만 표시하며, 이슈별 건수의 합계는 고유 사례 수보다 클 수 있다.
- 상세 페이지는 현재 메뉴 표시와 '탐색으로 돌아가기'를 제공한다. 기존 상세의 `?from=…` 값을 검증한 뒤 사용하여 목록 조건으로 복귀한다.
- 결과 개수, 조건 초기화, 검색 결과 없음 상태를 제공한다. 결과가 없는 상태도 같은 컨테이너 폭과 여백을 유지한다.
- 신규 콘텐츠의 제목·요약·이슈·분류·검색 별칭이 검색 데이터에 포함됐는지 확인한다. 분류 추론을 맹신하지 않고 가능하면 메타에 `theme_ids`를 지정한다.
- 포털은 `portal-data.js`의 리비전을 3초마다 확인하고, 변경되면 현재 검색어·필터를 유지한 채 사례 데이터를 다시 그린다. 이 자동 갱신은 사례 빌더가 `build_portal.py`를 실행해 리비전 파일을 새로 쓴 뒤 작동한다. 원본 메타만 수정해도 감지하는 파일 감시기는 아니다.
- Vercel의 열린 포털에는 운영 배포가 완료된 데이터가 반영된다. 로컬 빌드만으로 온라인 화면이 갱신되지는 않는다. 화면 코드 자체의 변경은 페이지 새로고침이 필요하다. 상대 상세 링크와 검색·필터 hash를 로컬·HTTPS에서 함께 유지한다.
- 일반 사례 차트의 상대강도/일별 회전율/누적 순매수 체크박스는 각각 패널 단위로 작동한다. 누적 순매수는 현재 개인·외국인·기관 묶음이다. 숨기면 패널·범례·hover 수치를 함께 접고 남은 패널과 X축을 재배치한다.
- 인적분할 쌍대 비교 차트는 `평가가격=100`과 `첫 종가=100`을 명시적으로 전환한다. 합산가치는 분할비율로 가중하고, 비교지수의 기준일이 다른 경우 차트 안내에 그 차이를 반드시 밝힌다. 평가가격을 적정가치로 표현하지 않는다.
- 현재 체크 상태는 새로고침하면 기본값으로 돌아온다. 전역 설정 저장 기능이 있다고 가정하지 않는다. 에쓰오일 전용 차트는 별도 템플릿이므로 이 체크박스가 자동 적용되지 않는다.
- 거시 인과지도는 단정적 예측이 아니라 조건부 전달 경로를 표시한다. 범용 DRAM·NAND 가격 경로는 계약가격과 현물가격을 구분하고, 제조사 원가·가격 전가·PC/스마트폰 수요를 별도 노드로 둔다. 완제품 가격·수요에는 반드시 `상승/감소 압력`으로 표기하며 재고, 장기계약, 마진 흡수, 사양·제품 믹스, 보조금과 교체주기의 완충 조건을 상세 패널에 함께 제공한다.
- LLM 성능→데이터센터 전력수요 경로는 AI 서비스 채택·사용량과 총 연산량을 같은 변수로 취급하지 않는다. 모델·소프트웨어 효율 개선, 기존 데이터센터 여유용량·가동률, 전력계약·계통접속·인허가를 중간 조건으로 밝힌다. 신규 데이터센터 착공이 즉시 전력수요를 만든다고 연결하지 않고, 준공·서버 설치·상업 가동 뒤의 `가동 IT 용량 × 이용률 × PUE`로 운영 전력수요를 검증한다. 후속 경로에서 `전력 부족`은 국가 전체의 절대 부족이 아니라 지역·시간대별 공급여력·계통접속 여유 하락 압력으로 표시하고, 전력가격은 시장구조·신규 투자비의 요금 배분에 따라 상승 또는 하락할 수 있음을 함께 밝힌다. 원전은 가스·재생에너지+저장·지열·수요반응과 경쟁하는 안정전원 선택지로 두며 규제·금융·건설 시차를 거쳐야 한다. 발전·망 투자는 실제 승인·발주 뒤 변압기·개폐장치·차단기와 전력케이블 수요로 연결한다. 케이블 소재는 구리로 단정하지 않고 가공선의 알루미늄과 지중·해저선의 구리·알루미늄 선택을 구분한다. ESS는 전기를 새로 생산하지 않고 충전한 전기를 시간 이동해 피크·혼잡을 완충하며, 장기간 에너지 부족을 단독 해결하지 못한다는 한계를 상세 패널에 표시한다.
- AI·로봇 투자→고용·소비·AI 서비스 매출 경로는 현대차·삼성전자·LG전자의 제조 AI·스마트공장 계획과 실제 순고용 감소를 구분한다. 업무 대체→노동소득→소비→내수 매출의 약화 경로만 단정하지 않고, 가격 인하·생산 확대·보완 업무·새 직무와 재교육·고용보험·소득이전의 완충 경로를 함께 표시한다. 정부 대응은 AI 직접 규제 외에 노동전환·사회안전망·조세·경쟁·안전·투명성 정책을 포함하며, 한국 AI 기본법이 고용 감소를 자동 금지한다고 표현하지 않는다. 기업 AI 지출은 GPU·데이터센터 등 `CapEx`와 API·구독·클라우드 등 통상 `OpEx`를 구분하고, 외부 상용 모델 선택→유료 좌석·API·토큰 사용→공급사 매출인식의 조건을 거쳐야 OpenAI·Anthropic 매출로 연결한다. AI 서비스 매출 증가를 이익·현금흐름 증가와 동일시하지 않는다.
- 중동 충돌→유가·물가·임금 2차 파급 경로는 전쟁 발생과 국제유가 상승을 직접 등치하지 않는다. 산유·수송 차질 위험, 실제 물량 감소와 보험·운임·위험 프리미엄, 대체 공급·여유생산능력·비축유를 분리한다. 유가 충격은 각국 `헤드라인 물가 상승 압력`으로 표시하되 근원물가 전이, 환율·세금·보조금·에너지 가중치의 국가별 차이를 밝힌다. 물가 상승과 노조의 임금 요구, 최종 명목임금 합의를 구분하고 교섭주기·물가연동·노동시장·협상력을 조건으로 둔다. 임금에서 제품·서비스 가격으로 가는 경로에는 생산성 차감 후 단위노동비용, 기업 마진과 가격결정력·수요를 중간에 두며, 임금 상승만으로 지속적인 임금–물가 악순환이 성립한다고 표시하지 않는다.

## 7. 새 페이지 추가 절차와 현재 자동 등록의 한계

1. 사례 상세, 별도 검증, 탐색 목록, 새 작업 메뉴 중 화면 역할을 정하고 가장 가까운 원본 템플릿을 선택한다.
2. 공통 셸·폰트·반응형·현재 메뉴 표시를 적용하고 분석 전용 CSS는 페이지 루트 아래로 범위를 제한한다. 정적 HTML은 `<!doctype html>`, `<html lang="ko">`, `<head>` 안의 `<meta charset="utf-8">`·viewport, 명시적 `<body>`를 포함한다. `dist` 파일을 원본으로 복사해 독립 수정하지 않는다.
3. 표준 사례는 가격·이벤트·메타 데이터를 준비하고 `data/cases.csv`와 대응하는 `data/navigation.json` 문구를 등록한다. 현재 표준 경로는 탐색 문구가 없는 CSV 행을 완전히 지원하지 않는다.
4. 별도 검증은 `data/meta/<고유이름>.json`과 대응하는 `dist/<종목코드>_<영문접미사>.html`을 생성한다. 파일명은 `tools/dist_names.py`가 ASCII로 맞춘다(한글 경로는 배포 시 404). `code`, `name`, `issue_type`을 넣고 카드용 `portal_title`, `portal_summary`, `theme_ids`, `event_date`, `event_label`, `aliases`를 권장한다.
5. 사례 빌더는 상세 HTML 생성 뒤 `build_portal.py`를 함께 실행한다. 포털 빌더는 메타·생성 HTML의 교집합을 자동 발견하고 검색 목록과 `portal-data.js`를 갱신한다. 이미 열려 있는 최신 포털은 리비전 변경을 자동 반영하며, 이 기능 추가 전에 열어 둔 페이지는 한 번 새로고침해야 한다.
6. 독립 실행하는 사례 빌더는 기본적으로 포털까지 갱신한다. 전체 빌드에서 중복 생성을 막을 때만 내부 옵션 `--skip-portal`을 사용하고 마지막에 포털을 한 번 생성한다. 새 빌더를 만들면 이 규칙과 전체 빌드 편입 여부를 명시하고 파일 대응표를 갱신한다.
7. 온라인 사례·대시보드 추가는 `python tools/deploy_dashboard.py`로 운영 배포와 고정 주소 파일 일치 검증까지 수행한다. 지수 레이더는 수집→검증→`build_index_radar.py`를 거쳐 전체 빌드에 포함된다. 절차와 장애 복구는 [배포 가이드](../docs/DEPLOYMENT.md)를 따른다.
8. 통합망은 포털의 사례 목록이 생성된 뒤 `build_causal_network.py`를 실행한다. `build_all.py`에는 포털 `--skip-network` 후 통합망 빌더를 명시적으로 편입했다. 개별 포털 빌드는 기본적으로 통합망도 갱신한다. 통합망용 Python 의존성은 `.venv-network`와 `requirements-network.txt`로 관리하며 원본·의존성·로컬 실행 이력은 배포 제외, 최종 HTML만 공개한다. 그래프에 추가할 새 가설은 `relations.json`에 명시하고 계열 매핑 중복은 빌드를 중단시켜 수정한다.

현재 자동 발견은 CSV에 등록된 종목코드를 제외하고 메타·생성 HTML의 대응을 찾는다. 따라서 **같은 종목의 두 번째 분석은 누락되거나 ID가 충돌할 수 있다.** 그런 기능을 추가할 때는 종목코드와 별개인 영구 사례 ID와 명시적 상세 경로로 수정해야 한다. 이 제약을 사례 중복 지원이 완료된 것으로 설명하지 않는다.

현재 사용 명령은 저장소 루트 기준이다.

```powershell
# 일반 사례 + 솔브레인·에쓰오일 검증 + 포털 갱신
python tools/build_all.py

# 전체 빌드 + Vercel 운영 배포 + 고정 주소 검증
python tools/deploy_dashboard.py

# 솔브레인 인적분할 쌍대 비교 화면과 포털 재생성
python tools/build_soulbrain_split.py

# 에쓰오일 별도 검증 화면과 포털 재생성
python tools/build_oil_link.py

# KOSPI 200 지수 레이더 원본 갱신·검증·화면 생성
python tools/fetch_index_data.py --index kospi200 --as-of 2026-09-04
python tools/validate_index_data.py --index kospi200
python tools/build_index_radar.py
python tools/build_index_radar_history.py
```

`build_all.py`는 일반 사례·솔브레인·에쓰오일 전용 빌더를 모두 호출한다. 상세 분석 데이터는 인라인하며 포털은 외부 리비전 파일을 함께 사용한다. 기본 배포 대상은 Vercel HTTPS이고 로컬 HTML 사용도 유지한다. 신규 정적 자산은 업로드 허용 목록과 상대 경로를 함께 확인한다.

## 8. 변경 확인과 문서 갱신

UI 변경 후 해당 빌드와 스크립트 문법 검사를 수행한다. 메뉴 변경은 모든 헤더 위치, 검색 변경은 검색 데이터·분류·결과 상세 경로까지 확인한다. 실제 브라우저 확인을 수행했다면 360/740/1024/1440px, 긴 제목·다수 메뉴, 키보드·확대, 밝은/어두운 모드 중 확인한 범위를 기록한다. 실행하지 않은 검증을 통과했다고 쓰지 않는다.

이 문서는 루트 `AGENTS.md`에 의해 이후 AI 디자인 작업의 필수 입력이자 함께 갱신하는 산출물이다. 디자인 변경 시 별도 지시 없이 다음을 수행한다.

1. 변경에 해당하는 본문·토큰·파일 대응표·현재 예외를 업데이트한다.
2. 변경일과 문서 버전을 갱신한다. 규칙의 의미가 바뀌면 소수 버전을 올린다.
3. 변경 이력에 적용 화면·이유·검증 결과를 남긴다.
4. 코드와 문서의 적용 범위가 일치하는지 확인하고 함께 완료 보고한다.

숫자·시세·분석 본문만 바뀌면 디자인 문서를 불필요하게 수정하지 않는다. 이 동기화는 AI 작업 규칙이며 파일 감시 서비스나 Git 훅이 아니다. 사람이 외부 편집기에서 바꾼 디자인 설명이 저절로 생성되지는 않는다.
