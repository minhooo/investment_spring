# 투자 샘터 — 디자인 및 페이지 확장 가이드

기준일: 2026-09-09 · 문서 버전: 1.42

이 문서는 새 페이지와 메뉴를 만들 때 읽는 공통 기준이다. 현재 구현을 기록한 부분과 앞으로 적용해야 할 규칙을 구분한다. 최초 기획 문서 `investment-spring-design.md`의 고정 사례 수·제안 단계 설명은 현재 구현의 기준으로 사용하지 않는다.

## 1. 제품과 화면의 역할

제품 이름은 **투자 아이디어 샘터**, 헤더 로고는 **투자 샘터**다. 목적은 투자 사례와 경제 변화의 경로를 찾아 읽고, 새로운 조사 질문을 만드는 개인 리서치 공간이다.

기본 접속 주소는 https://investment-spring.vercel.app 이다. 아래 `dist/` 경로는 로컬 산출물이며, 웹에서는 `dist/`를 제외한 동일 경로를 사용한다. 사례 탐색 고정 주소는 https://investment-spring.vercel.app/#cases 이다.

| 화면 | 사용자 목적 | 주소 |
|---|---|---|

### 단계별 확장 화면

`지수 레이더`의 현재 구성 MVP와 첫 History인 `2026년 상반기 KOSPI 200 정기변경`은 구현됐다. History는 리뷰 1건을 기준 페이지로 두고 편입 4종목을 같은 컷오프에서 비교하며, 종목별 영구 앵커를 제공한다. 임의의 두 스냅샷 비교, 완전한 규칙 엔진, 후보 신호, MSCI는 아직 구현되지 않았고 화면에 미리 노출하지 않는다. 다음 단계의 계약은 [`INDEX_RADAR_SPEC.md`](INDEX_RADAR_SPEC.md)를 따른다.

사례 수와 분류별 개수는 데이터로 계산한다. 문구에 '항상 5개' 같은 수를 고정하지 않는다. 사례는 관측된 내용, 인과지도는 조건에 따른 경로라는 차이를 유지한다. 한 사례는 여러 이슈에 연결될 수 있으므로, 사례 수와 이슈 연결 수는 구분해 표시한다.

## 3. 공통 시각 기준

새 페이지의 외부 셸은 통합 홈의 중립색 기준을 따른다. 분석 차트 내부에서는 의미가 정해진 색을 사용한다.

| 역할 | 밝은 모드 | 어두운 모드 |
|---|---|---|
| 전체 배경 `--background` | `#ffffff` | `#09090b` |
| 주요 텍스트 `--foreground` | `#18181b` | `#fafafa` |
| 카드 `--card` | `#ffffff` | `#18181b` |
| 보조 표면 `--muted` | `#f4f4f5` | `#27272a` |
| 보조 텍스트 `--muted-foreground` | `#71717a` | `#a1a1aa` |
| 테두리 `--border` | `#e4e4e7` | `#27272a` |
| 주 버튼 배경 / 글자 | `#18181b` / `#fafafa` | `#fafafa` / `#18181b` |

- 글꼴은 본문·메뉴·버튼·표·SVG 차트까지 `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, "Malgun Gothic", sans-serif`로 통일한다. 숫자는 다른 글꼴 대신 `font-variant-numeric: tabular-nums`를 사용한다.
- 현재 폰트 CDN은 `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css`다. 네트워크가 없으면 대체 폰트가 표시된다. 완전 오프라인 동일 폰트가 필요하면 로컬 폰트 포함을 별도 구현한다.
- 기본 본문 16px, 일반 조작/라벨 14px 이상, 보조 메타 12–13px. 기존 분석 차트의 작은 글자는 현재 예외이며 신규 화면에서 무조건 복제하지 않는다.
- 페이지 제목은 홈 기준 `clamp(28px, 4vw, 42px)`, 줄높이 1.2. 제목은 줄바꿈하고 고정 높이로 자르지 않는다.
- 기본 카드 반경 10px, 입력/버튼 약 8px, 얇은 1px 테두리와 작은 그림자. 강조는 색·굵기·선택 표면으로 표현한다.
- 여백은 4/8/12/16/24/32/48px 계열을 기본으로 하고 현재 셸 패딩 22px은 호환값으로 유지 가능하다.
- 링크는 이동, 버튼은 동작, 체크박스는 표시 선택에 사용한다. hover만으로 기능을 제공하지 않고 키보드 포커스를 보이게 한다.

일반 사례 차트의 의미색은 종목 보라, 비교지수 회색, 상대강도 초록, 회전율 금색, 외국인 파랑, 기관 주황, 개인 분홍이다. 국내 주가 상승 빨강·하락 파랑 표기를 유지하되 범례와 부호를 함께 표시한다. 새 차트 색의 의미가 다르면 반드시 라벨로 구분한다.

## 4. 공통 레이아웃과 모바일

새 화면의 기본 구조는 다음과 같다.

```text
공통 헤더: 투자 샘터 / 주요 메뉴 / 통합 검색
본문: 상위 위치·돌아가기 → 페이지 제목·한 문장 설명
      검색·필터 또는 주요 조작
      결과 목록 또는 분석 차트·표
      출처·기준일·관련 자료
공통 하단 안내
```

- 헤더 최대 너비 1180px, 탐색 본문 1060px, 분석 본문 1180px. 가운데 정렬하며 본문이 화면 너비를 넘지 않게 한다.
- 데스크톱 좌우 여백 22–24px, 모바일 16px. 새 페이지의 Grid 열에는 `minmax(0, 1fr)`, Flex 자식에는 필요 시 `min-width: 0`을 적용한다.
- 카드/컨트롤은 콘텐츠가 길어질 때 세로로 커져야 한다. 긴 한글 이름·영문·코드에도 줄바꿈되도록 한다. 문서 전체에 `overflow-x: hidden`을 넣어 잘림을 감추지 않는다.
- 차트·넓은 표는 자기 컨테이너 안에서만 가로 스크롤한다. 차트 최소 너비를 줄여 축·이벤트를 읽을 수 없게 만들지 않는다.
- 신규 화면은 740px 이하에서 목록 필터와 진입 카드를 1열로 전환한다. 440px 이하에서는 헤더 검색을 전체 너비의 별도 행으로 둔다.
- 기존 화면은 서로 다른 분기점을 쓴다: 포털 740/440px, 일반 사례 KPI 1020/600px 및 헤더 640px, 거시 셸 820px, 에쓰오일 KPI 900px. 실제 수정 대상의 기존 분기점과 충돌 여부를 확인한다.
- 밝은/어두운 모드에서 입력 배경·글자·테두리·선택 상태를 함께 맞춘다. 어두운 모드에 밝은 색을 고정한 카드가 섞이지 않도록 한다.

## 5. 페이지와 메뉴가 늘어날 때의 규칙

아래는 확장 시 적용할 기준이며 현재 사이드바·더보기 메뉴·페이지네이션이 구현됐다는 뜻은 아니다.

| 증가하는 대상 | 확장 방법 |
|---|---|
| 사례·종목·분석 보고서 | 기존 사례 목록에 추가. 개별 종목을 상위 메뉴로 만들지 않음 |
| 이슈·산업·테마 | 분류와 필터로 확장. 탭이 여러 줄을 차지하면 검색 가능한 선택기로 변경 |
| 독립적인 작업 목적 | 새로운 상위 메뉴 후보. 예: 실제 기능이 구현된 아이디어 노트 |
| 상위 메뉴 5개까지 | 헤더에서 주요 동작을 바로 제공. 긴 이름과 1024px 너비도 확인 |
| 6개 이상 또는 실제로 넘침 | 중요 메뉴 + '더보기' 또는 그룹 사이드바로 전환. 글씨를 줄여 끼워 넣지 않음 |
| 모바일 메뉴 증가 | 접을 수 있는 메뉴로 전환. 열림 상태, 닫기, 키보드 포커스와 현재 위치 제공 |
| 사례 수십~수백 건 | 필터·정렬 유지, 필요 시 페이지네이션 도입. 고정 임계치보다 로딩·스크롤 비용으로 판단 |

상위 메뉴는 작업 목적을 담은 짧은 명사로 이름 짓는다. 새 아이디어가 기존 사례/거시 경로로 충분히 표현되면 그 안에 추가한다. 홈 진입 카드가 늘면 `repeat(auto-fit, minmax(min(100%, 280px), 1fr))` 같은 적응형 열을 고려하고 마지막 카드 폭·긴 제목을 확인한다.

새 전역 메뉴 추가 시 헤더가 존재하는 모든 템플릿과 거시 셸을 함께 수정한다. `navigation.json`은 탐색 문구용이며 메뉴 정의가 아니다. 현재 전역 메뉴는 `data/site_navigation.json`과 `tools/site_shell.py`가 생성한다. 템플릿은 `<!--__SITE_NAV__-->` 자리표시자를 사용하고, 포털만 hash 현재 위치를 위해 `data-nav` 속성을 함께 받는다.

네 번째 상위 메뉴는 **`자금 레이더`**다. OpenDART 주요사항보고서의 상장사 유상증자·CB·BW·EB 발행결정 공시를 기준으로 조달수단·사용처·잠재 희석·전환/만기 일정을 살핀다. 실제 납입·자금 집행·상환과 투자판단은 별도 확인 대상으로 남긴다. 다섯 번째 상위 메뉴는 **`지수 레이더`**다. KOSPI 200부터 시작하되 특정 지수명에 종속되지 않으며, 현재 구성·과거 변경·발표 전 편입 조건을 한 작업 공간에서 다룬다. `현재 구성`과 `History`는 지수 레이더 내부 탭으로 왕복한다. History의 페이지 단위는 종목 하나가 아니라 정기변경 리뷰 하나이며, 같은 기준일·방법론·출처를 공유하는 종목은 한 페이지의 비교표와 종목별 앵커로 구성한다. 현재 구성은 네이버 구성목록과 키움 현재가·유통비율 기반 참고 비중을 제공하고, History는 키움 `ka10059` 관측과 증권사 추정값을 명시적으로 분리한다. 구성목록은 KRX 원본 교차검증 전 보조 출처이며, 공식 KRX 지수 비중과 KRX 지수주식수 기반 비중은 `—`로 표기한다. 후보 예측은 과거 시점 데이터만 사용한 검증을 갖춘 뒤 노출한다. 페이지·데이터·단계별 구현 계약은 [`INDEX_RADAR_SPEC.md`](INDEX_RADAR_SPEC.md)를 따른다.

## 6. 검색·상세 화면의 일관성

- 통합 인과망은 다섯 번째 상위 메뉴를 추가하지 않고 **거시 인과지도 내부 작업**으로 둔다. 거시 목록·상세에서 진입하며 공통 헤더의 거시 메뉴를 현재 위치로 표시한다. `개별 전달 경로`와 `통합 인과망·검증실`은 왕복 링크를 제공한다. 사례 탐색으로 직접 돌아가는 링크·사례 노드·종목·이슈·테마 소속은 표시하지 않는다. 통합 검색은 `인과망·시계열·검증실·알고리즘·네트워크` 검색으로 진입할 수 있다.
- 통합망의 현재 화면은 **가상 거시 데이터로 상호작용을 검증하는 캔버스 MVP**다. 12개 노드와 14개 방향 관계를 외생 충격→전달 매개체→시장 결과의 좌우 흐름으로 배치하고, 빈 캔버스 팬·휠/버튼 줌·노드 드래그·초기 배치 복원을 제공한다. 노드 클릭 시 모든 선행 원인과 후행 영향을 각각 청록/주황 외곽 강조로 표시하고, 관련 없는 노드·엣지는 12% opacity로 낮춘다. 선택한 노드 ID는 `node`, 선택한 엣지 ID는 `edge`, 경로 시작·결과 ID는 `from`·`to` URL 파라미터에 서로 배타적으로 보존한다.
- 가상 관계의 긍정 방향은 초록 실선·`+`, 부정 방향은 분홍 점선·`−`와 삼각 화살촉으로 구분한다. 연결선 hover에는 원인→결과와 관계 설명을 tooltip으로 제공한다. 클릭 또는 탭하면 원래 부호 색·선형을 유지한 채 굵은 포커스 underlay로 선택 엣지를 강조하고, 원인·결과 노드만 함께 강조하며 나머지 요소는 12% opacity로 낮춘다. 이 색과 부호는 가상 변수의 방향 예시이며 통계적 유의성·인과 확률·투자 점수가 아니다.
- Stitch 시안의 검정·남청 표면, 24px 점 그리드, 48px 앱 바, 왼쪽 안내 패널, 중앙 캔버스, 오른쪽 상세 패널을 사용한다. 패널은 Node Detail, Edge Detail, Causal Path 세 모드를 같은 스크롤 영역에서 전환한다. Node Detail Panel v1은 노드 역할·ID·정의, 가상 현재 값·단위·기준 시점·관측 주기·지역·분류, 한 문장 해석, 직접 상위 원인과 직접 하위 영향을 제공한다. 관계 카드는 원인→결과, 긍정/부정 부호, 관계 설명을 함께 표시하고 클릭 시 해당 노드로 그래프 중심과 상세 내용을 이동한다. Edge Detail Panel v1은 원인→결과, 부호, 전달 메커니즘, 성립 조건, 완충·반대 요인, 가상 전달 시차와 양 끝 노드 이동 버튼을 제공한다.
- Causal Path Explorer v1은 왼쪽 패널에서 시작 노드와 결과 노드를 선택하고 현재 가상 그래프에서 BFS로 찾은 가장 짧은 방향 경로 한 개를 표시한다. 경로의 모든 노드·엣지는 부호 색을 보존한 채 강조하고 경로 밖 요소는 12% opacity로 낮춘다. 오른쪽 패널은 각 단계의 원인→결과·부호·관계 설명, 이전/다음 단계, 전체 경로 맞춤을 제공한다. 단계 강조는 탐색 위치일 뿐 효과 크기·확률·중요도 순위가 아니다. 방향 경로가 없으면 그래프를 임의로 연결하지 않고 현재 가상 관계 범위의 빈 상태를 표시한다.
- 1024px 이하에서는 양쪽 패널을 독립 drawer로 접고 캔버스가 화면 전체를 사용한다. 최초 URL 복원에서는 상세 drawer를 닫아 두고 노드 또는 엣지를 클릭·탭하거나 경로 보기를 실행하면 연다. 경로 선택은 왼쪽 drawer의 기본 `<select>`와 실행 버튼으로 hover 없이 이용하고 실행 후 오른쪽 drawer로 전환한다. Cytoscape 터치 탭 허용 반경을 확대해 hover가 없는 모바일에서도 연결선을 선택할 수 있게 한다. 상세 drawer는 Tab 포커스 순환, Escape 닫기와 열기 버튼으로의 포커스 복귀를 제공한다. 밝은/어두운 모드를 함께 지원한다.
- 이번 MVP에는 인증, 데이터베이스, 뉴스 피드, AI, 가설 작성, 충격 시뮬레이터, 검증실과 공식 기준 변경 UI를 넣지 않는다. 화면의 값과 관계는 모두 `DEMO DATA`·`검증 전`으로 표시한다. `relations.json`의 정식 가설과 빌더의 재현 스냅샷은 변경하지 않았으며 가상 관계를 공식 인과망에 병합하지 않는다.
- 현재 예외: 빌더는 기존 거시 원문·관계 payload와 실행 스냅샷을 계속 생성하지만 캔버스 MVP는 이를 렌더링 입력으로 사용하지 않는다. 정식 데이터 전환은 단위·빈도·공개시점과 근거를 검토한 뒤 별도 승인 범위에서 수행한다. 3D·자동 재학습·서버 저장·과거 vintage 재현은 구현하지 않았다.

- URL에 검색어·필터·정렬을 보존한다. 기존 `#cases?issue=…&theme=…&pattern=…&q=…&sort=…`와 `#search?q=…` 흐름을 유지한다. 이슈는 쉼표로 연결한 복수 ID(`issue=rights,index-inclusion`)를 허용하며, 선택한 이슈 중 하나와 연결된 사례를 중복 없이 표시한다.
- 사례는 대표 이슈 하나에 고정하지 않는다. 포털 데이터의 `issue_ids`로 복수 이슈를 명시하고, 카드에는 연결된 이슈 태그를 모두 보인다. 사례별 목록은 같은 카드를 한 번만 표시하며, 이슈별 건수의 합계는 고유 사례 수보다 클 수 있다.
- 상세 페이지는 현재 메뉴 표시와 '탐색으로 돌아가기'를 제공한다. 기존 상세의 `?from=…` 값을 검증한 뒤 사용하여 목록 조건으로 복귀한다.
- 일반 사례 상세의 종목명·제목·질문·요약은 편집기 개행을 공백 하나로 정규화한 단일 논리 문장으로 렌더링한다. 제목에는 강제 균등 줄바꿈을 넣지 않고, 질문 요약은 불필요한 문자 폭 제한을 두지 않는다. 좁은 화면에서 생기는 자연스러운 줄바꿈은 유지하되 데이터의 줄바꿈이나 HTML 조각이 화면 줄을 강제하면 안 된다.
- 결과 개수, 조건 초기화, 검색 결과 없음 상태를 제공한다. 결과가 없는 상태도 같은 컨테이너 폭과 여백을 유지한다.
- 신규 콘텐츠의 제목·요약·이슈·분류·검색 별칭이 검색 데이터에 포함됐는지 확인한다. 분류 추론을 맹신하지 않고 가능하면 메타에 `theme_ids`를 지정한다.
- 포털은 `portal-data.js`의 리비전을 3초마다 확인하고, 변경되면 현재 검색어·필터를 유지한 채 사례 데이터를 다시 그린다. 이 자동 갱신은 사례 빌더가 `build_portal.py`를 실행해 리비전 파일을 새로 쓴 뒤 작동한다. 원본 메타만 수정해도 감지하는 파일 감시기는 아니다.
- Vercel의 열린 포털에는 운영 배포가 완료된 데이터가 반영된다. 로컬 빌드만으로 온라인 화면이 갱신되지는 않는다. 화면 코드 자체의 변경은 페이지 새로고침이 필요하다. 상대 상세 링크와 검색·필터 hash를 로컬·HTTPS에서 함께 유지한다.
- 일반 사례 차트의 상대강도/일별 회전율/누적 순매수 체크박스는 각각 패널 단위로 작동한다. 누적 순매수는 현재 개인·외국인·기관 묶음이다. 숨기면 패널·범례·hover 수치를 함께 접고 남은 패널과 X축을 재배치한다.
- 인적분할 쌍대 비교 차트는 `평가가격=100`과 `첫 종가=100`을 명시적으로 전환한다. 합산가치는 분할비율로 가중하고, 비교지수의 기준일이 다른 경우 차트 안내에 그 차이를 반드시 밝힌다. 평가가격을 적정가치로 표현하지 않는다.
- 현재 체크 상태는 새로고침하면 기본값으로 돌아온다. 전역 설정 저장 기능이 있다고 가정하지 않는다. 에쓰오일 전용 차트는 별도 템플릿이므로 이 체크박스가 자동 적용되지 않는다.
- 거시 인과지도는 단정적 예측이 아니라 조건부 전달 경로를 표시한다. 범용 DRAM·NAND 가격 경로는 계약가격과 현물가격을 구분하고, 제조사 원가·가격 전가·PC/스마트폰 수요를 별도 노드로 둔다. HBM 우선 생산배분은 같은 웨이퍼·클린룸 병목을 공유할 때만 비HBM 공급제약으로 연결하며 DRAM과 NAND를 같은 생산능력으로 합치지 않는다. 고객의 선구매·장기공급계약·재고 축적은 최종 실수요와 구분하고, 높은 고객 재고가 뒤의 주문 조정과 가격 하방 압력으로 되돌아오는 시차를 표시한다. 가격·수익성에서 중국 업체의 투자 결정, 공장·장비·수율·고객 인증을 거친 적격 양산, 실제 유효공급도 각각 분리한다. 완제품 가격·수요에는 반드시 `상승/감소 압력`으로 표기하며 재고, 장기계약, 마진 흡수, 사양·제품 믹스, 보조금과 교체주기의 완충 조건을 상세 패널에 함께 제공한다.
- LLM 성능→데이터센터 전력수요 경로는 AI 서비스 채택·사용량과 총 연산량을 같은 변수로 취급하지 않는다. 모델·소프트웨어 효율 개선, 기존 데이터센터 여유용량·가동률, 전력계약·계통접속·인허가를 중간 조건으로 밝힌다. 신규 데이터센터 착공이 즉시 전력수요를 만든다고 연결하지 않고, 준공·서버 설치·상업 가동 뒤의 `가동 IT 용량 × 이용률 × PUE`로 운영 전력수요를 검증한다. 후속 경로에서 `전력 부족`은 국가 전체의 절대 부족이 아니라 지역·시간대별 공급여력·계통접속 여유 하락 압력으로 표시하고, 전력가격은 시장구조·신규 투자비의 요금 배분에 따라 상승 또는 하락할 수 있음을 함께 밝힌다. 원전은 가스·재생에너지+저장·지열·수요반응과 경쟁하는 안정전원 선택지로 두며 규제·금융·건설 시차를 거쳐야 한다. 발전·망 투자는 실제 승인·발주 뒤 변압기·개폐장치·차단기와 전력케이블 수요로 연결한다. 케이블 소재는 구리로 단정하지 않고 가공선의 알루미늄과 지중·해저선의 구리·알루미늄 선택을 구분한다. ESS는 전기를 새로 생산하지 않고 충전한 전기를 시간 이동해 피크·혼잡을 완충하며, 장기간 에너지 부족을 단독 해결하지 못한다는 한계를 상세 패널에 표시한다.
- AI·로봇 투자→고용·소비·AI 서비스 매출 경로는 현대차·삼성전자·LG전자의 제조 AI·스마트공장 계획과 실제 순고용 감소를 구분한다. 업무 대체→노동소득→소비→내수 매출의 약화 경로만 단정하지 않고, 가격 인하·생산 확대·보완 업무·새 직무와 재교육·고용보험·소득이전의 완충 경로를 함께 표시한다. 정부 대응은 AI 직접 규제 외에 노동전환·사회안전망·조세·경쟁·안전·투명성 정책을 포함하며, 한국 AI 기본법이 고용 감소를 자동 금지한다고 표현하지 않는다. 기업 AI 지출은 GPU·데이터센터 등 `CapEx`와 API·구독·클라우드 등 통상 `OpEx`를 구분하고, 외부 상용 모델 선택→유료 좌석·API·토큰 사용→공급사 매출인식의 조건을 거쳐야 OpenAI·Anthropic 매출로 연결한다. AI 서비스 매출 증가를 이익·현금흐름 증가와 동일시하지 않는다.
- 중동 충돌→원유·LNG·물가의 2차 파급 경로는 전쟁 발생과 에너지 가격 상승을 직접 등치하지 않는다. 원유 생산·수송 차질과 호르무즈 LNG 항행·선적·보험 위험을 두 갈래 카드로 분리하고, 실제 물량 감소와 보험·운임·위험 프리미엄, 대체 공급·여유생산능력·비축유·가스 저장·수요감축을 구분한다. 유럽 TTF는 유가·석탄과 별도 변수로 두며 `EUR/MWh`, 현물/기준월물과 관측일을 고정한다. TTF→지역 도매 전력가격은 가스발전의 한계가격 설정 여부, 도매 전력가격→AI 채산성은 시장연동 계약·PPA 갱신과 실제 데이터센터 위치를 조건으로 표시한다. 장기 PPA·헤지·저탄소 발전믹스·가격상한·효율 개선·자가전원·지역 이전이 완충하면 세계 AI 산업 붕괴로 일반화하지 않는다. 유가·가스 충격은 헤드라인 물가 상승 압력으로 표시하되 근원물가 전이, 환율·세금·보조금·에너지 가중치의 국가별 차이를 밝힌다. 물가 상승과 노조의 임금 요구, 최종 명목임금 합의를 구분하고 교섭주기·물가연동·노동시장·협상력을 조건으로 둔다. 임금에서 제품·서비스 가격으로 가는 경로에는 생산성 차감 후 단위노동비용, 기업 마진과 가격결정력·수요를 중간에 두며, 임금 상승만으로 지속적인 임금–물가 악순환이 성립한다고 표시하지 않는다. 영국 장기금리와 미국 장기금리의 동행은 공통 글로벌 물가·정책·기간프리미엄 요인을 먼저 확인하며 국가 간 직접 인과선으로 표시하지 않는다.
- 장기국채금리→채권·자산가격 경로는 장기금리를 기대 단기금리 경로와 기간프리미엄으로 분해한다. 유가 상승은 기대인플레이션과 중앙은행의 긴축 반응 기대가 높아지는 조건에서만 기대 단기금리로 연결한다. 국채 순발행·양적긴축·회사채 대체 수요가 만드는 시장 장기채 순공급과 중앙은행·외국·연기금·보험의 구조적 장기채 수요를 반대 방향 요인으로 두며, 중국 등 한 주체만으로 장기금리를 설명하지 않는다. 기간프리미엄은 직접 관측값이 아닌 모형 추정치임을 밝힌다. 시장 요구수익률 상승→기존 고정금리 장기채 가격 하락은 약정 현금흐름이 같은 조건에서 별도 노드로 표시하고, 만기 상환 약정과 중도 가격·기회비용·재투자·인플레이션·부도 위험을 구분한다. 채권·주거용 부동산·주식·기업/상업용 부동산의 네 자산 경로는 넓은 화면 2열×2행, 740px 이하 1열로 배치한다. 10년물 5% 같은 단일 수준을 보편적인 증시 하락 임계값으로 표시하지 않는다.
- 장기금리 상세의 기존 현물채권·주거·주식·기업/상업용 부동산 네 카드는 유지하고, 한국 국채선물 경로는 넓은 화면에서 2열 전체폭 카드로 덧붙인다. 이 카드는 `선물가격·증거금률·실효 레버리지·일일정산 손실·추가증거금/포지션 축소`를 순서대로 보여주며 680px 이하에서는 다른 카드와 함께 1열로 전환한다. 현물채권과 선물을 같은 상품으로 합치거나 고정 배율·보장된 롤 수익·물타기 안전성을 화면 문구로 쓰지 않는다.
- 같은 장기금리 상세에서 미국 소형기업 분기는 넓은 화면 2열 전체폭, 680px 이하 1열 카드로 둔다. `기업 차환비용 → 소형기업 이자비용·차환 부담 → 투자·현금흐름·이익 하락 압력 → Russell 2000 상대성과 하방 압력`을 분리하고 변동금리 비중·만기벽·이자보상배율·신용스프레드와 지수 구성기업의 실제 이익 추정치 악화를 조건으로 표시한다. Russell 2000은 약 2,000개 미국 소형주 규모지수이지 고부채 기업만의 바스켓이나 자동 하락 상품이 아니다. E-mini RTY와 Micro M2K의 계약승수, 계좌별 가변 증거금, 선물의 금리·예상배당·만기 공정가치를 구분한다. 원월물 고가를 보장된 롤 수익으로 쓰지 않고, 인버스 ETF의 일일 재설정과 장기 경로의존성도 원금 자동 소멸로 일반화하지 않는다.
- 미국 교차상장·ADR 경로는 특정 기업을 노드로 만들지 않고 상장 사건, 거래 접근성, 미국 투자자 보유, 공시·투자자 보호, 유동성·가격 발견, 요구수익률을 일반 변수로 표시한다. 달러 표시와 미국 상장을 기업가치 증가와 같은 뜻으로 쓰지 않으며, ADR의 원주·전환비율 연동, 자기선택 편향, 상장·공시비용, 환율·예탁수수료를 상세 한계로 함께 보여 준다. 미국 재정·대외수지의 회계적 대응과 투자자의 국채·주식·예금·직접투자 배분은 같은 인과선으로 합치지 않는다.
- 한국 주택·PF→단기자금시장 경로는 기존 주택가격 하락과 사업장 분양수입·사업수지 악화를 같은 변수로 두지 않는다. 시행사·SPC 상환불능 위험에서 PF-ABCP·ABSTB 차환, 증권사 매입확약·시공사 보증, HUG·주금공·지자체 보증으로 갈라지는 계약별 위험 이전을 표시한다. 익스포저와 최종 손실, 지급불능과 단기 유동성 부족, 자산매각과 신용공급 축소도 각각 분리하며 PF 밖의 회사채·CP·RP 가격·발행·거래가 악화될 때만 시장 확산으로 판정한다. 정책 유동성·공적 보증·사업장 재구조화·정리는 차환과 유동성 압박의 완충 노드로 두되 신용손실 제거·즉시 지출·주택가격 부양과 동일시하지 않는다. 레고랜드 사례와 HUG 상품 설명은 메커니즘의 근거로 사용하지만 `부동산 하락=금융위기`, `전체 PF=정부 보증`, 프로그램 한도=실제 손실이라는 단정은 채택하지 않는다.
- 엔 캐리 경로는 미·일 단기금리 차이, USD/JPY 변동성, 위험조정 캐리 매력, 엔화 조달 익스포저, 환율, 청산, 대상통화·위험자산 매도를 서로 다른 노드로 둔다. 정책금리 차이나 스왑포인트를 확정수익으로 표현하지 않고 FX 베이시스·비용·환율손익·레버리지·마진을 조건으로 밝힌다. 은행대출·FX스왑·선물·리테일 FX는 범위와 빈도가 다른 대리치이므로 한 총량으로 합치지 않는다. 엔화 강세와 위험자산 하락을 모두 캐리 청산 탓으로 돌리지 않으며 정책개입·안전자산 수요·미국 지표·기술주 밸류에이션 등 동시 원인을 한계에 표시한다.

- 자사주 장내매입→대형주 수급·KOSPI 기여 경로는 취득 결의와 실제 체결, 거래대금·호가 대비 매수 강도, 종목 가격 지지 압력, 시가총액 가중 지수 기여, 프로그램 종료, 취득 후 소각·임직원 보상·보유·처분을 분리한다. 발표 예정금액·기타법인 순매수·실제 자사주 체결액을 같은 값으로 표시하지 않는다. 가격 지지는 조건부 주문흐름 효과로만 표현하고 가격 하한·무조건 상승·매입 종료 뒤 자동 급락을 쓰지 않는다. KOSPI 기여도는 종목 비중과 수익률을 사용하되 KOSPI 200의 유동시가총액 방식과 혼용하지 않는다. 솔리다임 IPO는 2026년 9월 4일 재공시에서 확정되지 않았으므로 충격 노드나 선으로 표시하지 않는다.

- 증분 병합의 작은 분기는 기존 경로의 끝에 공통 `cid-rate-lanes cid-memory-lanes`·버튼·화살표를 재사용해 붙인다. 이번 적용은 LLM·전력 상세의 미국 프로젝트 금융/현금 부족 두 카드, 엔 캐리 상세의 일본 수입물가·종합 CPI 카드, 장기금리 상세의 재무부 바이백·비지표물 유동성 카드다. 넓은 화면 2열, 기존 680px 이하 1열 기준을 따르며 신규 메뉴·전용 페이지·폰트·색을 만들지 않는다. 기존 공통 헤더·거시 복귀·밝은/어두운 모드의 적용 범위를 유지하고 `navigation.json`의 노드 목록·검색 별칭도 함께 등록한다.
- 새 일본 물가 노드는 글로벌 물가 노드와 구별하고, AI 보증 상한·발효·지급·최종손실과 바이백의 시장기능·가격효과도 상세에서 분리한다. 투자자 체결 순매매 합계는 상계되므로 잔여 주문불균형으로 표시하지 않는다. 새로운 `hypothesis_notes`는 기존 연결 상세의 설명 영역을 사용하며 통계 점수나 별도 레이어를 만들지 않는다.

## 7. 새 페이지 추가 절차와 현재 자동 등록의 한계

1. 사례 상세, 별도 검증, 탐색 목록, 새 작업 메뉴 중 화면 역할을 정하고 가장 가까운 원본 템플릿을 선택한다.
2. 공통 셸·폰트·반응형·현재 메뉴 표시를 적용하고 분석 전용 CSS는 페이지 루트 아래로 범위를 제한한다. 정적 HTML은 `<!doctype html>`, `<html lang="ko">`, `<head>` 안의 `<meta charset="utf-8">`·viewport, 명시적 `<body>`를 포함한다. `dist` 파일을 원본으로 복사해 독립 수정하지 않는다.
3. 표준 사례는 가격·이벤트·메타 데이터를 준비하고 `data/cases.csv`와 대응하는 `data/navigation.json` 문구를 등록한다. 현재 표준 경로는 탐색 문구가 없는 CSV 행을 완전히 지원하지 않는다.
4. 별도 검증은 `data/meta/<고유이름>.json`과 대응하는 `dist/<종목코드>_<영문접미사>.html`을 생성한다. 파일명은 `tools/dist_names.py`가 ASCII로 맞춘다(한글 경로는 배포 시 404). `code`, `name`, `issue_type`을 넣고 카드용 `portal_title`, `portal_summary`, `theme_ids`, `event_date`, `event_label`, `aliases`를 권장한다.
5. 사례 빌더는 상세 HTML 생성 뒤 `build_portal.py`를 함께 실행한다. 포털 빌더는 메타·생성 HTML의 교집합을 자동 발견하고 검색 목록과 `portal-data.js`를 갱신한다. 이미 열려 있는 최신 포털은 리비전 변경을 자동 반영하며, 이 기능 추가 전에 열어 둔 페이지는 한 번 새로고침해야 한다.
6. 독립 실행하는 사례 빌더는 기본적으로 포털까지 갱신한다. 전체 빌드에서 중복 생성을 막을 때만 내부 옵션 `--skip-portal`을 사용하고 마지막에 포털을 한 번 생성한다. 새 빌더를 만들면 이 규칙과 전체 빌드 편입 여부를 명시하고 파일 대응표를 갱신한다.
7. 온라인 사례·대시보드 추가는 `python tools/deploy_dashboard.py`로 운영 배포와 고정 주소 파일 일치 검증까지 수행한다. 지수 레이더와 자금 레이더는 각각 수집→검증→전용 빌더를 거쳐 전체 빌드에 포함된다. 절차와 장애 복구는 [배포 가이드](../docs/DEPLOYMENT.md)를 따른다.
8. 통합망은 포털의 거시 경로 목록이 생성된 뒤 `build_causal_network.py`를 실행한다. `build_all.py`에는 포털 `--skip-network` 후 통합망 빌더를 명시적으로 편입했다. 개별 포털 빌드는 기본적으로 통합망도 갱신한다. 통합망용 Python 의존성은 `.venv-network`와 `requirements-network.txt`로 관리하며 원본·의존성·로컬 실행 이력은 배포 제외, 최종 HTML만 공개한다. 그래프에 추가할 새 가설은 `relations.json`에 명시한다. 사례 탐색 데이터는 통합망 입력으로 사용하지 않는다.

현재 자동 발견은 CSV에 등록된 종목코드를 제외하고 메타·생성 HTML의 대응을 찾는다. 따라서 **같은 종목의 두 번째 분석은 누락되거나 ID가 충돌할 수 있다.** 그런 기능을 추가할 때는 종목코드와 별개인 영구 사례 ID와 명시적 상세 경로로 수정해야 한다. 이 제약을 사례 중복 지원이 완료된 것으로 설명하지 않는다.

현재 사용 명령은 저장소 루트 기준이다.

```powershell
# 일반 사례 + 솔브레인·에쓰오일 검증 + 포털 갱신
python tools/build_all.py

# 전체 빌드 + Vercel 운영 배포 + 고정 주소 검증
python tools/deploy_dashboard.py

# 솔브레인 인적분할 쌍대 비교 화면과 포털 재생성
python tools/build_soulbrain_split.py

# 에쓰오일 별도 검증 화면과 포털 재생성
python tools/build_oil_link.py

# KOSPI 200 지수 레이더 원본 갱신·검증·화면 생성
python tools/fetch_index_data.py --index kospi200 --as-of 2026-09-04
python tools/validate_index_data.py --index kospi200
python tools/build_index_radar.py
python tools/build_index_radar_history.py

# 자금 레이더 원본 검증·화면 생성
python tools/validate_financing_data.py
python tools/build_funding_radar.py
```

`build_all.py`는 일반 사례·솔브레인·에쓰오일 전용 빌더를 모두 호출한다. 상세 분석 데이터는 인라인하며 포털은 외부 리비전 파일을 함께 사용한다. 기본 배포 대상은 Vercel HTTPS이고 로컬 HTML 사용도 유지한다. 신규 정적 자산은 업로드 허용 목록과 상대 경로를 함께 확인한다.

## 8. 변경 확인과 문서 갱신

UI 변경 후 해당 빌드와 스크립트 문법 검사를 수행한다. 메뉴 변경은 모든 헤더 위치, 검색 변경은 검색 데이터·분류·결과 상세 경로까지 확인한다. 실제 브라우저 확인을 수행했다면 360/740/1024/1440px, 긴 제목·다수 메뉴, 키보드·확대, 밝은/어두운 모드 중 확인한 범위를 기록한다. 실행하지 않은 검증을 통과했다고 쓰지 않는다.

이 문서는 루트 `AGENTS.md`에 의해 이후 AI 디자인 작업의 필수 입력이자 함께 갱신하는 산출물이다. 디자인 변경 시 별도 지시 없이 다음을 수행한다.

1. 변경에 해당하는 본문·토큰·파일 대응표·현재 예외를 업데이트한다.
2. 변경일과 문서 버전을 갱신한다. 규칙의 의미가 바뀌면 소수 버전을 올린다.
3. 변경 이력에 적용 화면·이유·검증 결과를 남긴다.
4. 코드와 문서의 적용 범위가 일치하는지 확인하고 함께 완료 보고한다.

숫자·시세·분석 본문만 바뀌면 디자인 문서를 불필요하게 수정하지 않는다. 이 동기화는 AI 작업 규칙이며 파일 감시 서비스나 Git 훅이 아니다. 사람이 외부 편집기에서 바꾼 디자인 설명이 저절로 생성되지는 않는다.
