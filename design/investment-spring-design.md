# 투자 아이디어 샘터 — 통합 대시보드 설계 명세

> 이 문서는 최초 설계 기록이다. 현재 화면 기준은 [DESIGN_GUIDE.md](DESIGN_GUIDE.md), 고정 주소와 배포 방법은 [운영 가이드](../docs/DEPLOYMENT.md)를 따른다. 현재 서비스: https://investment-spring.vercel.app

작성일: 2026-09-06 · 상태: 설계 제안 · 대상: 후속 Terra 구현

이 문서는 기존 프로젝트를 읽고 작성한 화면·탐색·데이터 연결 설계다. 이번 작업에서는 서비스 코드, 데이터, 기존 대시보드를 수정하거나 배포하지 않는다. 함께 제공하는 대화 내 미리보기는 화면 흐름을 확인하기 위한 모형이며 실제 대시보드 구현물이 아니다.

## 1. 결정 요약

제품 이름은 **투자 아이디어 샘터**, 짧은 로고명은 **투자 샘터**를 추천한다. 홈에서만 “나만의 투자 아이디어 샘터”라는 문장을 보조적으로 사용한다.

상위 메뉴는 **홈 / 사례 탐색 / 거시 인과지도**, 세 개로 시작한다.

- **홈:** 무엇을 살펴볼지 고르는 출발점. 두 작업의 입구, 통합 검색, 테마, 질문형 바로가기를 제공한다.
- **사례 탐색:** 과거 사건에서 어떤 일이 벌어졌고 무엇을 배울 수 있는지 찾는다. 사례 5개를 모두 보여주고 필터로 좁힌다.
- **거시 인과지도:** 경제 변수의 변화가 산업·기업·자산으로 전달되는 경로를 살펴본다. 현재 두 경로를 선택한다.

핵심 구분은 **사례 = 실제로 벌어진 일**, **인과지도 = 조건에 따른 전달 경로**다. 산업 테마는 두 콘텐츠를 함께 찾는 연결 기준이다. 사례를 읽는 것만으로 특정 거시 가설이 검증된 것으로 표현하지 않는다.

브랜드는 친근하게, 기능명은 바로 이해되게 쓴다. ‘샘물 뜨기’, ‘씨앗 심기’ 같은 은유를 메뉴마다 반복하지 않는다. ‘대시보드 1·2’, ‘과제 1·2’, 영어 브랜드 MacroWeave는 새 통합 메뉴명으로 사용하지 않는다.

## 2. 확인한 현재 프로젝트

| 자산 | 현재 상태 | 통합 시 역할 |
|---|---|---|
| `data/cases.csv` | 사례 5행, 이슈·종목·패턴·문서/대시보드 경로 보유 | 사례 색인의 원천 |
| `cases/유상증자/*.md` | 이수페타시스·삼성SDI·포스코퓨처엠 | 사건 설명, 당시 판단, 사후 확인, 교훈 |
| `cases/지수편입/*.md` | 에코프로머티리얼즈·알테오젠 | 같은 역할 |
| `data/meta/*.json` | 헤드라인·국면·교훈 등 | 기존 상세 화면 및 탐색 요약 연결 |
| `tools/build_dashboard.py` | 가격·이벤트·수급을 계산하고 HTML에 데이터 삽입 | 기존 계산 경로 유지 |
| `tools/dashboard_template.html` | 공용 차트·표·교훈 템플릿 | 상세 화면 유지, 공통 메뉴·돌아가기 추가 |
| `dist/*_dashboard.html` | 5개 산출물 존재 | 기존 링크 계속 사용 |
| `design/causal-investment-dashboard.html` | 에너지/금리 전환, 노드 상세 표시 가능 | 거시 화면의 출발 소스 |
| `design/causal-investment-dashboard-preview.html` | srcdoc iframe을 포함한 미리보기 포장 | 통합 소스로 사용하지 않음 |
| `INDEX.md`, `framework/` | 분류사전·대조사례·판단원칙 | 큐레이션과 태그 정의의 근거 |

거시 화면의 ‘변수·기업·테마 검색’, ‘새 인과 추가’, ‘시나리오’, ‘관심 종목’, ‘근거 보관함’, ‘원화 약세 경로’는 현재 소스에서 이에 대응하는 업무 동작을 확인하지 못했다. 단기/중기/장기 버튼은 선택 표시만 바꾸며 계산하거나 다른 데이터를 불러오지 않는다. 통합 후 기능이 완성된 메뉴처럼 노출하지 않는다. 에너지 경로 안에 환율 관련 노드가 있지만 독립적인 원화 약세 지도는 아직 없다.

프로젝트는 현재 Python + 정적 HTML 구조이며 루트에 Git 저장소나 프런트엔드 패키지 구성이 없다. 이번 통합을 위해 React/Next.js, DB, 로그인, 검색 서버를 도입할 필요는 없다.

이 문서는 금융 내용의 외부 사실 검증 보고서가 아니다. 사례 내용과 거시 경로는 저장소에 기록된 콘텐츠로 취급한다.

## 3. 정보구조와 화면 이동

```text
투자 아이디어 샘터
├─ 홈
│  ├─ 통합 검색 → 검색 결과 → 사례 상세 / 인과지도 상세
│  ├─ 사례 탐색으로 → 전체 사례 5개
│  ├─ 거시 인과지도로 → 경로 2개
│  ├─ 테마로 둘러보기 → 해당 테마의 사례 + 인과지도
│  └─ 질문으로 찾아보기 → 미리 정한 필터의 사례 목록
├─ 사례 탐색
│  ├─ 전체 / 유상증자 / 지수편입
│  ├─ 산업·테마, 패턴, 키워드 필터
│  └─ 사례 상세 → 같은 유형 사례 / 탐색으로 돌아가기
└─ 거시 인과지도
   ├─ 에너지 가격 충격 → 한국 반도체
   └─ 장기국채금리 상승 → 부동산·주식
      └─ 노드 선택 → 조건·시차·반대 경로
```

홈에서 사례 목록까지 1회, 특정 사례까지 일반적으로 2회 클릭이면 도달한다. 특정 종목명으로 통합 검색하면 결과에서 바로 상세를 연다. 5개 종목을 각각 상위 메뉴로 만들지 않는다. 이슈 유형도 별도 사이트나 중간 분류 페이지로 나누지 않는다.

‘테마’는 별도 상위 메뉴가 아니라 공통 필터다. 사례와 거시 경로를 함께 보는 테마 결과 화면을 재사용한다. 이 방식이면 메뉴를 추가하지 않고도 새로운 산업과 사례가 들어온다.

검색과 두 입구가 화면 상단에서 보이게 한다. 큰 일러스트, 홍보용 히어로, 주가지수 전광판은 필요하지 않다. 홈에는 사례 전체 표를 중복해서 넣지 않는다. 전체 5개는 ‘사례 탐색’에서 바로 보인다.

질문형 바로가기는 저장된 필터다. 자연어 AI 답변이나 별도 비교 분석기가 아니다. 클릭하면 선택된 필터와 실제 사례가 나타나므로 왜 그 결과가 나왔는지 알 수 있다.

첫 버전에서는 최근 본 항목·즐겨찾기·메모 보관함을 추가하지 않는다. 이후 필요해지면 홈 아래에 ‘다시 볼 자료’를 넣고, 기기 내 저장인지 동기화인지 별도로 결정한다.

### 테마의 초기 연결안

다음은 탐색 편의를 위한 **새로운 편집 분류 제안**이다. 기존 CSV에 있는 필드라고 가정하지 않는다. 중복 소속을 허용하며 카드 수 합계를 전체 콘텐츠 수로 표시하지 않는다.

| 테마 ID | 화면명 | 사례 연결 | 거시 경로 연결 |
|---|---|---|---|
| `battery-ess` | 2차전지·ESS | 삼성SDI, 포스코퓨처엠, 에코프로머티리얼즈 | 없음 |
| `ai-infra` | AI 인프라 | 이수페타시스, 삼성SDI, 포스코퓨처엠 | 에너지 가격 충격 → 한국 반도체 |
| `bio` | 바이오 | 알테오젠 | 없음 |
| `energy-power` | 에너지·전력 | 없음 | 에너지 가격 충격 → 한국 반도체 |
| `rates-assets` | 금리·자산가격 | 없음 | 장기국채금리 상승 → 부동산·주식 |

AI 인프라의 사례 연결 근거: 이수페타시스·삼성SDI의 케이스 태그, 포스코퓨처엠의 케이스/메타에 기록된 ESS 및 AI 데이터센터 관련 교훈. 삼성SDI·포스코퓨처엠을 반도체 기업으로 분류하는 것이 아니다. ‘AI 인프라’를 통해 함께 발견할 뿐, 에너지 충격을 검증한 직접 사례라고 표시하지 않는다.

## 5. 사례 탐색 화면

### 필터 구조

```text
사례 탐색
[종목명·종목코드·이슈·패턴 검색                         ] [검색]
[전체 5] [유상증자 3] [지수편입 2]
산업·테마 [전체 ▾]   패턴 [전체 ▾]       정렬 [사건 최신순 ▾]
선택한 조건: [유상증자 ×] [2차전지·ESS ×]     조건 초기화
2개 사례

삼성SDI             006400 · 유상증자 · 2025.03.14 공시

```

위 두 행은 구성 예시다. 실제 사건 최신순에서는 포스코퓨처엠이 삼성SDI보다 먼저다.

분류는 세 축으로 구분한다.

| 축 | 사용자 질문 | 예시 |
|---|---|---|
| 이슈 유형 | 무슨 사건이 있었나? | 유상증자, 지수편입 |
| 산업·테마 | 어떤 분야가 궁금한가? | 2차전지·ESS, AI 인프라, 바이오 |
| 패턴 | 어떤 전개를 찾는가? | 수요 지연, 악재 철회, 재료 소진 |

상단 이슈 탭은 단일 선택, 산업·테마와 패턴은 각각 단일 선택으로 시작한다. 축 사이는 AND 조건이다. 하나의 콘텐츠가 여러 테마를 가질 수 있는 것과 사용자가 여러 필터를 동시에 고르는 것은 구분한다. 5건에서 복잡한 다중 선택 UI는 필요하지 않다.

카드는 세로 목록형이다. 제목, 사건일, 한 줄 탐색 요약, 테마, 대표 패턴 최대 2개, ‘사례 열기’ 순서로 배치한다. 상세 태그와 유형코드 G·I1 등의 정보는 상세 화면으로 내려보낸다. 사례 5개를 페이지 나눔 없이 모두 렌더링한다. 30건 이상이 되면 페이지당 20건 같은 정책을 다시 결정하되 이번 구현에는 선제 도입하지 않는다.

정렬은 **사건 최신순 / 종목명순**만 제공한다. 사건 최신순은 아래의 `event_date` 내림차순, 동률이면 `id` 오름차순이다. 파일 수정시간은 분석 최신일로 쓰지 않는다. 수익률·스코어 순위는 첫 버전에 넣지 않는다.

### 초기 사례 등록표

| `case-5` | 포스코퓨처엠 — 증자 진행 신호와 이후 성과의 엇갈림 | 2025-05-13 공시 | 유상증자 | 혼합 용도, 수요 지연 | `dist/003670_포스코퓨처엠_dashboard.html` |

카드 제목은 기존 사례를 식별하기 쉽게 다시 쓴 편집 문구다. 기존 문서 제목과 상세 헤드라인을 덮어쓰지 않는다. 위 `event_date`는 저장소 메타·케이스에 기록된 공시/발표일을 명시적으로 등록한다.

**사건일과 성과 기준일은 다르다.** 현재 CSV의 `기준일`은 삼성SDI 2025-03-13, 포스코퓨처엠 2025-05-12, 에코프로머티리얼즈 2023-11-17, 알테오젠 2024-03-05다. 이를 공시/편입일로 표시하지 않는다. 상세에서는 사건일·차트 기준일·데이터 마지막 날짜를 각각 구분한다.

### 패턴 표시·검색 사전

기존 태그 ID를 유지하고 사용자용 띄어쓰기·설명을 별도로 제공한다.

| 화면 표시 | 검색 연결 ID | 검색 별칭 |
|---|---|---|
| 수요 지연 | `수요지연` | 수요지연 |
| 악재 분해 | `악재분해` | 악재분해 |
| 악재 철회 후 반등 | `철회반등` | 악재 철회, 철회반등 |
| 재료 소진 | `재료소진` | 재료소진, 기대 소진 |
| 선반영 과열 | `선반영과열` | 선반영과열 |
| 선반영 없음 | `선반영없음` | 선반영없음 |

실제 패턴 선택지는 등록된 전체 패턴 중 선택한 이슈·테마와 교집합이 있는 것에서 생성한다. 두 개의 대표 패턴만 카드에 표시하더라도 검색은 등록된 전체 패턴을 대상으로 한다. 패턴별 건수는 기존 CSV의 `핵심패턴태그`를 기준으로 계산한다. 본문에만 있는 태그를 몰래 추가하지 않는다.

## 6. 통합 검색과 테마 결과

첫 버전 검색은 로컬 키워드 검색이다. ‘이 상황에서 어떤 종목을 사야 할까’에 답하는 생성형 AI 기능으로 표현하지 않는다.

홈에서는 검색 폼을 크게 한 번 보여주고, 다른 화면에서는 상단 공통 헤더에 축약형 통합 검색을 둔다. 사례 목록의 검색은 ‘사례 안에서 검색’이라고 접근성 이름을 붙여 범위를 구별한다. Ctrl+K는 통합 검색 입력에 초점을 주며, 필수 기능이 아닌 편의 단축키다.

검색 결과는 **사례 / 인과지도**로 묶는다. 각 결과에 콘텐츠 종류, 제목, 일치한 태그/별칭을 표시한다. 각 그룹 건수는 0건도 보여주되 빈 그룹에 가짜 결과를 넣지 않는다.

- `삼성SDI`, `006400`, `SDI` → 해당 사례를 먼저 표시.
- `유증` → `유상증자` 별칭으로 사례 3건.
- `지수 편입`, `MSCI` → 이슈·경로 별칭에 맞는 사례.
- `2차전지`, `이차전지`, `배터리` → `battery-ess`의 사례 3건.
- `AI 인프라` → 사례 3건 + 거시 경로 1건. 결과에 ‘공통 테마’로 표시.
- `금리` → 장기국채금리 경로. 관련 사례는 0건.
- `수요 지연` → 삼성SDI·포스코퓨처엠 2건.
- `반도체` → 에너지 경로. PCB를 반도체 기업과 동일시하지 않는다.

### 검색 규칙

1. Unicode NFKC 정규화, 영문 소문자화, 앞뒤 공백 제거. 문장부호·`#`는 검색 인덱스에서 구분 문자로 처리한다.
2. 검색 별칭 사전의 가장 긴 구절을 먼저 표준어로 변환한다. 예: ‘지수 편입’→‘지수편입’, ‘수요 지연’→‘수요지연’, ‘AI 인프라’→‘ai-infra’. 남은 단어는 공백으로 나눈다.
3. 모든 검색 단어가 해당 항목의 검색 필드 중 어디엔가 존재해야 한다(AND). 빈 검색은 선택된 필터의 전체 결과다. 모든 단어를 이어붙인 완전일치 보조 키도 두어 회사명의 불필요한 공백을 허용한다.
4. 검색 필드: 종목명·6자리 코드·카드 제목·편집 요약·이슈·전체 등록 패턴·테마 이름/별칭·명시적 별칭. 거시는 경로 제목·등록된 노드명·변수/기업명·테마/별칭.
5. 우선순위는 전체 검색어가 코드/종목명 정확히 일치 → 제목 일치 → 태그/별칭 일치 → 요약 일치. 같은 순위에서는 사례의 사건 최신순, 거시의 등록 순서를 사용한다. 불투명한 ‘AI 유사도’ 수치를 표시하지 않는다.
6. 긴 문서 본문·수급 시계열은 첫 버전 검색 대상에서 제외한다. 사례 5개와 지도 2개에 외부 검색 서비스나 벡터 DB는 필요 없다.
7. 목록 필터는 즉시 반영하고 검색어는 Enter/검색 버튼으로 확정한다. 한글 IME 조합 중 Enter는 확정 검색으로 처리하지 않는다.
8. 이슈 탭 건수는 해당 이슈의 전체 등록 건수다. 실제 필터 결과 수는 ‘N개 사례’로 별도 표시한다. 이 두 의미를 혼용하지 않는다.

빈 결과 문구: **“일치하는 자료가 없습니다.”** 현재 검색어·선택 조건과 ‘조건 초기화’를 표시한다. 자동으로 필터를 풀어 다른 결과를 보여주지 않는다. 테마에 사례가 없으면 **“이 테마에 등록된 사례가 없습니다.”**라고 표시한다.

## 7. 사례 상세의 통합 방식

기존 상세 차트·수급·국면 표·교훈을 중심으로 유지한다. 공통 상단 메뉴와 위치 표시 `홈 > 사례 탐색 > 종목명`을 추가한다.

상세 상단에는 ‘탐색으로 돌아가기’와 **“이 사례에서 볼 질문”** 한 줄을 둔다. 결과 숫자를 홈에서 크게 강조하지 않고, 상세 화면의 기존 성과 영역에서 확인한다.

첫 통합 버전에서 필요한 변경은 공통 메뉴, 탐색 복귀, 하단 관련 사례 링크다. 기존 차트의 기간 전환·호버·이벤트 선택 기능을 다시 작성하지 않는다. 기본/상세 탭으로 전체 보고서를 재편하는 작업은 이번 범위에 넣지 않는다.

관련 사례는 `같은 이슈 유형` 또는 명시적으로 지정한 대조 사례로 제시한다. 예: 삼성SDI → 포스코퓨처엠은 ‘같은 유상증자·2차전지, 다른 자금용도와 수요 도착 시점’. 관련 이유 없이 ‘추천 종목’이라고 표시하지 않는다.

당시 판단과 사후 확인은 기존 문서의 분리를 유지한다. 최초 버전은 사후 분석 아카이브이므로 결과를 가리는 학습 모드는 제공하지 않는다. 카드의 사후 요약을 당시 알려진 판단인 것처럼 쓰지 않는다.

수익률을 이후 목록에 추가한다면 `D+250 초과수익`과 `기준일부터 데이터 마지막 날까지 초과수익`을 분리해야 한다. 결과태그는 프로젝트 정의에 따라 D+250 기준이며 최근 초과수익의 부호로 바꾸지 않는다. 현재 CSV의 최근 초과수익에는 기준 날짜 필드가 없으므로 탐색 카드의 ‘현재 수익률’로 바로 노출하지 않는다. 숫자가 필요해지면 기존 계산 함수에서 날짜와 함께 산출한다.

## 8. 거시 인과지도 화면

거시 상위 메뉴를 누르면 **경로 목록**을 먼저 보여준다. 2개의 경로를 짧게 훑고 바로 선택할 수 있게 한다.

| ID | 이름 | 설명 | 표시 상태 |
|---|---|---|---|
| `energy` | 에너지 가격 충격 → 한국 반도체 | 에너지·전력비 변화가 AI 투자와 반도체로 전달되는 조건 | 예시 경로 |
| `rates` | 장기국채금리 상승 → 부동산·주식 | 대출 부담과 할인율을 통해 자산가격에 전달되는 조건 | 예시 경로 |

‘예시 경로’는 현재의 정적 가설 설명이라는 뜻이다. 실시간 분석·예측·검증 완료 같은 배지는 쓰지 않는다. 기존 +20% 문구는 시나리오의 가정이며 계산 결과가 아님을 표시한다.

상세 구성은 공통 상단 메뉴 + ‘경로 목록으로’ + 현재 경로 선택 + 지도 + 노드 설명이다. 기존 MacroWeave 상단바와 WORKSPACE 사이드바는 통합 셸로 대체하여 이중 메뉴를 없앤다. ‘시나리오’라는 별도 메뉴 대신 에너지/금리를 고르는 경로 선택기를 둔다.

노드 선택 시 설명·성립 조건·시차·반대 경로를 보여준다. 단기/중기/장기가 내용이나 모델을 바꾸지 않는 동안에는 선택 버튼 대신 현재 경로의 시간 범위를 텍스트로 표시한다. 출처명이 있어도 URL이 없는 항목은 원문 링크처럼 꾸미지 않는다.

모바일에서는 지도를 축소하여 글씨를 작게 만들지 않고 기존 순서형 노드 목록을 활용한다. 선택 노드 상세는 지도 아래로 이동한다.

공통 테마의 사례는 경로 아래에서 **“같은 테마의 사례”**로 연결할 수 있다. 다만 첫 버전에서는 홈의 테마 검색으로 양쪽 콘텐츠가 함께 발견되는 데까지만 필수로 한다. 노드별 사례 연결은 명시적 연결 근거가 준비된 뒤 추가한다. ‘금리 → 2차전지’ 같은 관계를 사례가 있다는 이유만으로 새로 만들지 않는다.

## 9. URL과 복귀 규칙 — 정적 구조 권장안

정적 파일 서버의 경로 재작성 없이 동작하도록 허브 내부는 hash 경로를 권장한다. 예시는 가독성을 위해 한글을 그대로 썼으며 실제 생성 시 URLSearchParams로 인코딩한다.

| 목적 | 권장 URL |
|---|---|
| 홈 | `dist/index.html#home` |
| 사례 전체 | `dist/index.html#cases` |
| 유상증자 필터 | `dist/index.html#cases?issue=rights` |
| 유상증자 + 배터리 | `dist/index.html#cases?issue=rights&theme=battery-ess` |
| 수요 지연 바로가기 | `dist/index.html#cases?pattern=수요지연` |
| 통합 검색 | `dist/index.html#search?q=삼성SDI` |
| 테마 통합 결과 | `dist/index.html#search?theme=ai-infra` |
| 거시 경로 목록 | `dist/index.html#macro` |
| 거시 상세 | `dist/macro.html?scenario=energy` |
| 거시 특정 노드 | `dist/macro.html?scenario=energy&node=ai` |
| 사례 상세 | 기존 `dist/<코드>_<종목>_dashboard.html` |

hash의 `?` 이후는 location.search가 아니라 hash를 분리한 뒤 URLSearchParams로 해석한다. 직접 링크·새로고침·앞으로/뒤로가기를 지원한다.

필터 변경은 history 항목을 추가해 뒤로가기로 되돌릴 수 있게 한다. 검색 확정도 하나의 이동이다. 기본값은 URL에서 생략하며 알 수 없는 필터는 제거 후 작은 안내를 보여준다.

상세로 이동할 때 `from`에 내부 허브의 hash 부분만 인코딩하여 전달한다. 예: `from=cases%3Fissue%3Drights`. 돌아가기 대상은 허용된 `home/cases/search/macro` hash만 수용하고 외부 URL은 받지 않는다. 복귀할 때 사용했던 검색어·필터·정렬이 살아 있어야 한다. 새 탭/직접 진입으로 `from`이 없으면 사례 목록 또는 거시 목록으로 돌아간다.

스크롤 복원은 같은 브라우저 탭의 sessionStorage에 탐색 URL별 scrollY와 마지막 선택 사례 ID를 저장해 구현할 수 있다. 저장이 차단되어도 URL 필터 복귀는 동작해야 한다. 영속적인 최근 기록/즐겨찾기를 이 저장에 섞지 않는다.

## 10. 데이터 계약과 변경할 파일 — 후속 구현 지침

### 원천 분리

- 기존 CSV: 사례 ID·회사·시장·이슈·패턴·기존 경로의 원천으로 유지.
- 기존 메타 JSON/MD: 상세 콘텐츠의 원천으로 유지.
- 새 `data/navigation.json`: 탐색 전용 편집 정보만 저장. 카드 제목/요약, 사건일, 테마 소속, 별칭, 대표 태그, 경로 등록 정보, 질문형 바로가기.
- 새 `data/taxonomy.json`: 테마/이슈 ID·표시명·별칭 사전. 기존 태그 원칙과 일치시킨다. 신규 ESS 같은 표시 테마는 원본 패턴 태그를 임의 변경하지 않는다.
- 빌더가 이 원천을 합쳐 허브 HTML에 탐색용 JSON을 인라인한다. 실행 시 CSV/JSON fetch가 필요하지 않도록 한다.

navigation.json의 사례 항목에는 종목코드·성과 숫자·원본 대시보드 경로를 다시 복사하지 않는다. `case_id`로 CSV와 조인한다. 새 테마와 편집 요약은 navigation.json이 단일 원천이다.

```text
  aliases: string[]

QuestionShortcut
  id, label: string
  target_hash: string                   # 정해진 필터만 사용
```

초기 `issue_id` 매핑은 유상증자→rights, 지수편입→index-inclusion. 원본의 한국어 값은 바꾸지 않는다. 신규 이슈가 들어오면 사전에 등록하고 같은 목록/상세 구조를 사용한다.

동일 회사의 다른 사건은 별도 사례다. 현재 산출물명은 종목코드 기반이라 같은 회사 2건이 생기면 충돌한다. 이번 5건에서는 유지하고, 6번째 사례가 같은 회사일 경우 빌더 입력·파일명을 case_id 기반으로 확장한 뒤 기존 링크 호환을 따로 처리한다. 허브는 지금부터 코드 대신 case_id를 기본 키로 쓴다.

소스 CSS/JS는 빌드 시 HTML로 삽입해도 된다. 허브·상세에 동일 셸 소스를 사용하여 메뉴명을 여러 파일에 하드코딩하지 않는다. 셸 CSS는 `#spring-shell` 등의 범위로 제한한다. 현재 사례 템플릿의 전역 CSS와 거시 화면의 `#macro-causal-dashboard` 스타일이 충돌하지 않도록 한다.

거시 참고 파일은 HTML fragment이므로 제품용 출력에서는 문서 구조·문자 인코딩·viewport를 감싼다. preview.html의 iframe/srcdoc을 다시 삽입하지 않는다. 통합 셸과 거시 내용은 같은 문서에서 한 번만 렌더링한다.

`dist/`로 시작하는 CSV 경로는 허브 출력 기준으로 정규화하여 `dist/dist/...`가 되지 않게 한다. 데이터 문자열은 HTML escape 또는 textContent로 넣고, 인라인 JSON의 `</script>`도 이스케이프한다. .env나 인증정보는 탐색 인덱스·배포 산출물에 넣지 않는다.

## 11. 시각 설계와 반응형

시각 방향은 **차분한 개인 리서치 서재**다. 기존 사례 차트의 전문적인 정보 밀도는 살리고, 입구와 목록에는 여백을 더 둔다. 공통 강조색은 기존 사례 템플릿의 보라색 계열을 재사용한다. ‘샘터’를 표현하는 물 그림은 필요 없다.

- 글꼴: Pretendard Variable을 기본 글꼴로 사용하고, 숫자는 같은 글꼴의 tabular-nums 기능으로 정렬.
- 본문 16px, 일반 라벨 14px 이상, 메타데이터 12~13px 이상. 제목 크기를 과도하게 키우지 않는다.
- 홈 입구 두 개는 같은 크기·강조 수준. 어느 작업도 부속 기능처럼 보이지 않게 한다.
- 카드 전체를 클릭 가능한 div로 만들지 않고 제목/주요 동작을 실제 링크로 제공한다. 내부 필터와 링크의 중첩 클릭을 피한다.
- 상승/하락색은 기존 차트 의미를 유지하고 메뉴 강조에 사용하지 않는다.
- 데스크톱: 상단 가로 메뉴, 홈 입구 2열, 사례 목록 1열. 3개 메뉴에 고정 사이드바는 필요하지 않다.
- 768px 미만: 상단 브랜드/검색과 메뉴를 두 줄로 배치, 홈 입구 1열. 세 메뉴는 숨기지 않아도 된다.
- 360px: 검색 버튼·필터는 줄바꿈, 긴 종목명은 자연스럽게 줄바꿈. 페이지 전체 가로 스크롤 금지. 차트의 기존 가로 탐색 필요 여부는 상세 영역 안에서 처리한다.
- 선택 상태는 색과 밑줄/테두리·aria-current/aria-pressed로 표현. 키보드 포커스 유지, 주요 터치 대상 약 44px 확보.

## 12. 빈 상태와 데이터 상태

| 상황 | 화면 동작 |
|---|---|
| 아직 검색하지 않음 | 사례 목록은 전체 5개, 통합 검색은 테마 선택 안내 |
| 필터/검색 결과 없음 | 0건 문구, 현재 조건, 조건 초기화 |
| 특정 테마에 사례 없음 | 사례 0건 표시, 존재하는 거시 경로는 계속 표시 |
| 등록된 상세 산출물 누락 | ‘대시보드 준비 중’, 깨진 상세 링크 비활성화; 빌드 경고 |
| 잘못된 사례/지도 ID | 찾을 수 없음 + 목록으로; 다른 항목으로 몰래 대체하지 않음 |
| 잘못된 node ID | 해당 지도 정상 표시 + 노드를 찾지 못했다는 안내 |
| 잘못된 필터 ID | 미지원 조건 안내 후 그 조건만 제거 |
| 탐색 JSON 필수 필드 누락/ID 중복 | 검증 실패로 빌드 중단, 기존 산출물 덮어쓰지 않음 |
| 검색 인덱스 실행 오류 | 자료를 불러오지 못했다는 안내, 홈/기존 상세로 이동 가능 |
| 저장소 접근 실패 | 필터 URL 복귀 유지, 스크롤 복원만 생략 |

초기 콘텐츠는 인라인이므로 가짜 로딩 시간이나 스켈레톤을 넣을 필요가 없다. 새 빌더는 검증이 끝난 임시 산출물을 최종 경로로 교체하도록 구성한다.

## 13. 구현 순서와 완료 기준

### 1단계 — 입구 통합

공통 메뉴, 홈의 두 입구, 거시 목록, 기존 사례/거시 상세의 공통 메뉴와 돌아가기. 기존 5개 차트가 그대로 동작하는지 먼저 확인한다.

### 2단계 — 원하는 사례 찾기

사례 색인 5건 생성, 카드 목록, 이슈 탭, 테마·패턴 필터, 키워드/별칭 검색, 사건일 정렬, URL 상태 보존.

### 3단계 — 샘터 경험 완성

홈 테마 통합 결과, 질문형 바로가기 3개, 통합 검색의 콘텐츠별 그룹, 관련 사례 링크, 모바일 배치와 빈 상태. **이번 통합의 완료 범위는 1~3단계 전체**다.

즐겨찾기, 개인 메모, 나의 가설 노트, 사례 비교 전용 화면, AI 자연어 답변, 실시간 거시 데이터, 가설 편집·저장, 로그인/동기화는 별도 후속 과제다. 첫 버전 메뉴에 빈 자리나 작동하지 않는 버튼으로 미리 넣지 않는다.

### 수용 시나리오

1. 홈을 열면 스크롤 없이 두 작업 입구와 검색을 인지한다.
2. ‘사례 탐색’을 열면 사례 5건이 보인다. 유상증자 3건, 지수편입 2건이다.
3. `유상증자 + 2차전지·ESS`는 삼성SDI와 포스코퓨처엠 2건이다.
4. `수요 지연`은 같은 2건, `유증`은 3건, `006400`은 삼성SDI 1건이다. 코드의 0이 사라지지 않는다.
5. `AI 인프라` 테마 결과는 사례 3건·인과지도 1건이다. ‘가설 검증 사례’로 표현하지 않는다.
6. `금리` 검색은 장기국채금리 지도 1건·사례 0건이다.
7. 사건 최신순은 포스코퓨처엠 → 삼성SDI → 이수페타시스 → 알테오젠 → 에코프로머티리얼즈다.
8. 필터 상태에서 사례를 열고 ‘탐색으로 돌아가기’를 누르면 같은 검색·필터·정렬을 유지한다. 새로고침·뒤로가기도 정상이다.
9. 기존 5개 상세 링크를 직접 열어도 차트가 동작하고 홈/목록으로 이동할 수 있다.
10. 거시 경로 energy/rates 직접 링크와 노드 선택이 동작한다. 상태만 바꾸는 시간 버튼이나 빈 메뉴는 노출하지 않는다.
11. 존재하지 않는 검색어·ID·파일에 정의된 빈 상태가 나타난다. 필터를 조용히 풀어 결과를 부풀리지 않는다.
12. 데스크톱 1024px 및 736px, 모바일 360px에서 메뉴·검색·긴 종목명·필터가 겹치지 않는다. 키보드로 주요 흐름을 이용할 수 있다.
13. 새 사례는 CSV/메타/편집 분류 등록 후 빌드하면 목록·검색·건수가 갱신된다. 템플릿에 카드나 건수를 추가로 손대지 않는다.
