# 통합 인과망 확장 체크리스트

적용 대상: Codex·Claude를 포함해 통합 인과망·시계열 검증실에 노드, 연결, 계열, 판단 기준, 화면을 추가하는 모든 작업자.

이 문서는 정식 인과망 편입 작업의 순서를 고정한다. 통계적 선행 예측은 구조적 인과도, 투자 추천도, 매매 신호도 아니다. 상세 계약과 현재 구현 범위는 반드시 [`CAUSAL_NETWORK_SPEC.md`](CAUSAL_NETWORK_SPEC.md), UI 계약은 [`DESIGN_GUIDE.md`](DESIGN_GUIDE.md)를 우선해 함께 읽는다.

대량 원문을 자료별로 분석하는 단계는 먼저 [`CAUSAL_ANALYSIS_BATCH_WORKFLOW.md`](CAUSAL_ANALYSIS_BATCH_WORKFLOW.md)를 따른다. 사용자가 즉시 편입을 명시하지 않았다면 후보 카드와 수집 로그까지만 갱신하며, 이 문서의 정식 병합·전체 빌드·배포 절차를 원문마다 자동 실행하지 않는다. 증분 병합 또는 100건 전체 감사에 사용자가 동의한 뒤에만 이 체크리스트를 적용해 공식 인과망을 바꾼다.

## 1. 시작 전 확인

1. 루트 `AGENTS.md`, 이 문서, `CAUSAL_NETWORK_SPEC.md`, `DESIGN_GUIDE.md`를 읽는다. 원문 후보를 배치로 병합하는 작업이면 `CAUSAL_ANALYSIS_BATCH_WORKFLOW.md`와 수집 로그도 읽는다.
2. 새 내용이 기존 거시 경로의 노드·관계로 표현되는지 먼저 확인한다. 사례 탐색의 종목·이슈·테마·사례 카드는 이 화면에 추가하지 않는다. 같은 경제 변수를 다른 이름으로 중복 생성하지 않는다.
3. 추가하려는 것이 아래 중 무엇인지 명시한다.

| 종류 | 원본 | 화면 의미 |
|---|---|---|
| 인과 가설 | `data/causal/relations.json` | 보라색 방향 화살표. 조건부 경제 가설 |
| 경로 소속 | 거시 경로·변수 메타 | 회색 점선. 방향·효과를 주장하지 않음 |
| 시계열 후보 | `tools/network_analysis.py` 실행 결과 | 초록색 방향 화살표. 사전 정의된 검사에서 살아남은 선행 예측력 |
| 공식 판단 기준 | `data/causal/policy.json` | 버전·이유를 가진 운영 기준 |

## 2. 새 가설과 노드

1. 새 노드는 설명 원문이 있는 거시 경로 또는 명시적 데이터 원천에 귀속한다. 이름, 단위, 관측 빈도, 지역, 시차를 적는다.
2. 새 화살표는 `relations.json`의 `paths` 또는 `bridges`에 원인·결과·부호를 명시한다. bridge에는 서로 다른 경로를 연결하는 조건을 쓴다.
   - 개별 경로의 근거·조건·한계·시차는 `hypothesis_notes`의 `hypothesis:<원인>:<결과>` 키로 보강할 수 있다. 기존 연결만 참조하며 새 연결 선언을 대신하지 않는다. 후보 배치의 채택·재사용·보류 ID와 출처 해시는 `data/causal/merges/`에 남긴다.
3. 부호만으로 충분하지 않다. 생성 원문의 상세 패널에 작동 메커니즘, 반대 경로·완충 조건, 관측 불가능한 항목을 함께 쓴다.
4. ‘관련 있어 보임’, 동일 테마, 동일 종목이라는 사실만으로 화살표를 만들지 않는다. 중복 변수 병합은 개념·단위·지역·시점이 동일할 때만 한다.
5. 기존 가설을 통계 결과로 덮어쓰지 않는다. 후보가 0개여도 가설을 삭제하거나 기준을 자동 완화하지 않는다.

## 3. 계열과 시계열 검사

1. 계열을 추가하기 전 수정주가/수준/수익률, 기준시장, 실제 관측 시각, 공개·수정(vintage) 한계를 기록한다.
2. 같은 거시 변수의 원본이 여럿이면 측정 정의·지역·빈도를 문서화해 하나를 선택한다. 사례 종목 가격이나 편의상 골라 쓴 대리변수로 거시 변수를 대체하지 않는다.
3. 검정 가족은 결과를 보기 전에 정의한다. 성과가 좋은 쌍만 사후 추가하지 않는다.
4. 결측을 임의 보간하지 않고, 완료되지 않은 주·비정상 간격·미래 정보 누출을 검사한다.
5. `tools/test_network_analysis.py`와 `tools/test_causal_network_scope.py`를 실행한다. 정책·입력·코드·환경 해시가 보존된 `data/causal/runs/<run-id>.json`을 함께 검토한다.

## 4. 판단 기준 변경

1. 브라우저 초안은 탐색용이며 localStorage에만 남는다. 초안 저장·내보내기는 재학습이나 공식 기준 변경이 아니다.
2. 운영 기준을 바꾸려면 `policy.json`의 버전과 이유를 수정하고, 변경 전후의 후보·탈락 사유·검정 가족을 비교한다.
3. 종합점수로 통계, 예측오차, 부호 안정성, 경제적 근거를 합산하지 않는다. 각각의 수치와 한계를 별도로 보여 준다.
4. 장기금리·부동산·고용처럼 월/분기·발표시차가 중요한 변수는 현재 주간 가격 모형에 억지로 넣지 않는다. 별도 빈도·vintage·검증 계약을 만든 뒤 통합한다.

## 5. 화면·빌드·배포

1. 그래프 UI 또는 탐색 동선을 바꾸기 전 `DESIGN_GUIDE.md`의 공통 셸·색 의미·반응형 규칙을 적용하고, 같은 작업에서 본문·파일 대응표·변경 이력을 갱신한다.
2. CSS는 셸과 패널을, Cytoscape 2D는 배치·확대·선택을 담당한다. 노드 수 증가만으로 3D를 기본값으로 바꾸지 않는다. `전체 상세`·`군집 개요`·`주변 연결`은 배치와 라벨 밀도만 달리할 수 있고 같은 계위의 도형·색은 바꾸지 않는다. 현재 거시 경로는 보라색 둥근 사각형, 경제 변수는 파란색 원이다.
3. `python tools/build_all.py` 또는 인과망 단독 빌드를 실행해 `dist/causal-network.html`을 원본에서 생성한다. `dist/`만 직접 수정하지 않는다.
4. 최소한 분석 단위 테스트와 생성 성공을 확인한다. UI를 바꿨다면 그래프 선택·레이어·상세·모바일·밝은/어두운 모드를 실제 브라우저에서 확인한다. `주변 연결`은 작은 1단계 망뿐 아니라 노드 수가 많은 1·2단계 망에서 자동 확대, 라벨 겹침, 노드 간 최소 간격을 함께 검사한다.
5. 운영 반영은 `python tools/deploy_dashboard.py`로 전체 빌드·Vercel 배포·고정 주소 파일 일치 검증까지 마친다. 실행하지 않은 검증을 문서에 통과했다고 기록하지 않는다.

## 6. 커밋 경계

- 가설·계열·정책·분석 엔진·템플릿·생성 HTML·문서를 하나의 재현 가능한 기능 단위로 커밋한다.
- 생성물은 원본 변경과 같은 커밋에 포함한다. 개인용 스크린샷, 브라우저 다운로드, `artifacts/`, 임시 메모, 가상환경은 별도 요청이 없으면 포함하지 않는다.
- 새 기능은 이 문서와 `CAUSAL_NETWORK_SPEC.md` 중 실제로 바뀐 계약을 함께 최신화한다.
