# 대시보드 설계 규격

케이스마다 **같은 축·같은 지표·같은 색**으로 그린다. 케이스끼리 비교가 되려면 시각화가 표준화되어야 한다.

---

## 1. 왜 명목 주가가 아니라 상대값인가

명목 수익률은 **시장이 준 몫과 종목이 번 몫을 섞어버린다.**

이수페타시스 실측이 그 증거다.

| | 값 |
|---|---|
| D-day(2024-11-08) 이후 명목 수익률 | **+259.8%** |
| 같은 기간 KOSPI | **+161.1%** |
| **실제 초과수익** | **+98.7%p** |

"유증 이후 260% 올랐다"는 서술은 KOSPI가 161% 오른 장이었다는 사실을 감춘다.
케이스 스터디의 목적이 **이 이슈가 주가에 무슨 짓을 했는가**를 아는 것이라면,
시장 전체 효과는 반드시 빼야 한다.

## 2. 핵심 지표 — 상대강도 RS

```
RS(i) = ( 종목종가(i) / 종목종가(기준일) )
      ÷ ( 지수종가(i) / 지수종가(기준일) ) × 100
```

- **RS = 100** → 기준일 이후 지수와 똑같이 움직임
- **RS > 100** → 지수 초과 (아웃퍼폼)
- **RS < 100** → 지수 미달 (언더퍼폼)

기준일 선택은 **2-1절**을 따른다 — 공시 충격을 아직 반영하지 않은 마지막 거래일 종가.

### RS를 반드시 봐야 하는 3가지 순간

1. **RS 최저점** — 명목 주가의 저점과 **다르다.**
   이수페타시스의 가격 저점은 2024-12-02였지만, RS 저점은 **2024-12-12(제이오 인수 강행 발표일)** 이었다.
   가격은 이미 반등 중이었으나 시장 대비로는 그날이 바닥이다. **RS 저점이 악재 확정 시점을 짚는다.**
2. **RS 100 회복일** — 이슈의 충격이 완전히 소화된 날. 회복까지의 **거래일 수**가 케이스 간 비교 지표가 된다.
   (이수페타시스: D+51거래일)
3. **RS 고점 이후의 하락** — 명목 주가가 높아도 초과수익은 반납 중일 수 있다.
   (이수페타시스: RS 304 → 138)

## 2-1. 기준일(D-day) 선택 규칙 ★

기준일은 **공시 충격을 아직 반영하지 않은 마지막 거래일 종가**로 잡는다.
이걸 틀리면 케이스 간 비교가 무너진다.

| 공시 시점 | 기준일 | 예시 |
|---|---|---|
| **장 마감 후** | 공시일 종가 (그날은 아직 깨끗함) | 이수페타시스 2024-11-08 |
| **장중 / 장 시작 전** | **직전 거래일 종가** | 삼성SDI — 공시 2025-03-14, **기준일 2025-03-13** |

> 삼성SDI는 공시 당일 -6.2%가 이미 종가에 들어가 있다. 공시일을 기준일로 잡으면
> 초기 충격이 -5.9%p → -2.2%p로 축소되어 실제보다 순한 케이스로 기록된다.

`meta.json` 에서 `dday`(기준일)와 `announce_date`(공시일)를 **분리해서** 적고,
`dday_note` 에 왜 그 날을 골랐는지 남긴다. 대시보드가 이 문구를 그대로 표시한다.

## 3. 벤치마크 선택 규칙

| 종목 | 벤치마크 |
|---|---|
| 유가증권시장 상장 | **KOSPI** |
| 코스닥 상장 | **KOSDAQ** |
| 업종 효과를 분리하고 싶을 때 | 업종지수를 **추가** 계열로 (지수를 대체하지 말 것) |

한 차트에 벤치마크는 **하나만** 둔다. 여러 개를 겹치면 무엇 대비 초과인지 흐려진다.

## 4. 데이터 계약 (3개 파일)

케이스 하나 = 아래 3개 파일. 파일명 키는 `<종목코드>_<종목명>` 으로 통일한다.

### ① `data/prices/<key>.csv` — 시계열 (자동 생성)

```
date,close,volume,bm_close,bm_name
2024-11-08,30877.0,4082077,2561.15,KOSPI
```

- `tools/fetch_prices.py` 가 생성. 손으로 만들지 않는다.
- **수정주가**를 쓴다 (권리락·유무상증자 반영). 유상증자 케이스에서 원주가를 쓰면 권리락 하락이 주가 하락으로 잘못 잡힌다.
- 종목과 지수의 거래일이 어긋나는 행은 버린다(inner join).

### ② `data/events/<key>.csv` — 이벤트 (수작업)

```
date,phase,category,impact,title,detail,verified,source
```

| 컬럼 | 허용값 | 비고 |
|---|---|---|
| `date` | YYYY-MM-DD | 휴장일이면 **다음 거래일로 자동 스냅**되고 대시보드에 "→ 반영일" 표기 |
| `phase` | `PRE` `T0` `T1` `T2` | `10_판단프레임.md`의 시간축 3단계 |
| `category` | 공시 / 규제 / 계약 / 일정 / 시장 / 실적 | |
| `impact` | 긍정 / 부정 / 중립 / **미확인** | 마커 색을 결정 |
| `verified` | 확정 / 보도 / **미확인** | 미확인은 대시보드에 경고 문구로 표시 |

> **`미확인` 이벤트를 반드시 남길 것.** `analyze.py` 가 거래량 급증일을 자동 탐지해준다.
> 사유를 모르는 급등락일은 지우지 말고 `미확인`으로 기록한다 — 그게 다음 리서치 과제다.

### ③ `data/meta/<key>.json` — 케이스 메타 (수작업)

대시보드의 텍스트를 전부 여기서 공급한다. 마크다운 케이스 문서와 **내용이 어긋나면 안 된다.**
주요 키: `headline` `thesis` `type_code` `use_of_proceeds[]` `rules[]` `caveats[]`

## 5. 파이프라인

```bash
# 1) 시세 수집 — 종목코드 종목명 벤치마크 시작일 종료일
python tools/fetch_prices.py 007660 이수페타시스 KOSPI 20240102 20260906

# 2) 수치 산출 (구간수익률·초과수익·RS·거래량 급증일) — 케이스 문서에 붙여넣을 마크다운 출력
python tools/analyze.py "data/prices/007660_이수페타시스.csv" 2024-11-08

# 3) 대시보드 빌드 -> dist/<key>_dashboard.html
python tools/build_dashboard.py 007660_이수페타시스
```

**계산은 전부 빌드 스크립트에 있고, 템플릿은 그리기만 한다.** 수치 로직이 두 곳에 생기면 문서와 대시보드가 갈라진다.

상세 대시보드의 분석 데이터는 빌드 결과 HTML에 인라인한다. 포털은 인라인 기본값과 `portal-data.js` 리비전 갱신을 함께 사용한다. 현재 서비스는 https://investment-spring.vercel.app 이며, `python tools/deploy_dashboard.py`로 전체 빌드·운영 배포·파일 일치 검증을 수행한다. 배포 구조와 갱신 범위는 [운영 가이드](../docs/DEPLOYMENT.md)를 따른다.

## 6. 차트 규격

### 2단 구성 (하나의 x축 공유)

| 패널 | 내용 | 이유 |
|---|---|---|
| 상단 | **정규화 주가** — 종목과 지수를 기준일=100으로 | 두 계열의 스케일이 다르므로 절대 **이중 축을 쓰지 않는다.** 공통 기준으로 지수화해서 한 축에 올린다 |
| 하단 | **상대강도 RS** — 100 기준선 + 영역 채움 | 초과/미달이 한눈에 읽히도록 |

### 색 규칙 (국내 관례 준수)

| 역할 | 색 | 비고 |
|---|---|---|
| 종목 라인 | 남보라 (실선 2.2px) | 계열 정체성 |
| 벤치마크 라인 | 회색 (파선 2px) | 기준선이지 경쟁 계열이 아님 |
| 상대강도 RS | 청록 (실선 + 영역) | 파생 지표라 별도 색 |
| **상승 / 호재** | **적** | **국내 관례** |
| **하락 / 악재** | **청** | **국내 관례** |
| 중립·미확인 | 회색 | |

> 등락 표시색(적/청)과 계열 식별색(남보라/회색/청록)을 **분리**한다. 섞으면 "파란 선 = 하락"으로 오독된다.

### 이벤트 마커

- 번호 배지 + 아래로 내려가는 세로선. 배지 번호는 **이벤트 테이블 행 번호와 일치**한다.
- 클러스터 충돌은 **5레인 배치**로 회피 (같은 레인은 최소 간격 확보).
- 색만으로 의미를 전달하지 않는다 — 번호·범례·테이블이 항상 함께 있다.
- 배지/행 클릭 시 양방향 하이라이트.

### 음영

D-day → RS 100 회복일 구간을 옅게 칠한다 = **악재 반영 구간**. 회복 소요 거래일을 범례에 표기.

## 7. 케이스를 새로 추가할 때 체크리스트

- [ ] `fetch_prices.py` 로 시세 수집 (기간은 D-day **1년 전**부터 — 이슈 이전의 정상 상태가 있어야 비교가 된다)
- [ ] `analyze.py` 실행 → 거래량 급증 상위 10일 확인 → 모르는 날은 `미확인` 이벤트로 등록
- [ ] `events.csv` 작성 (공시 원문 기준, phase 표기)
- [ ] `meta.json` 작성 — 마크다운 케이스 문서와 내용 일치 확인
- [ ] `build_dashboard.py` 실행
- [ ] `INDEX.md` 한 줄 + `data/cases.csv` 한 행 (**초과수익 기준**으로 결과 태그 판정)

## 8. DART 원문 조회 (`tools/dart.py`)

```bash
python tools/dart.py corp 006400                    # 고유번호
python tools/dart.py piic 006400 20240101 20261231  # 유상증자결정 — 신주수·발행주식총수·자금용도 항목별 금액
python tools/dart.py list 006400 20250301 20250731  # 공시 이력 — 정정·발행조건확정·청약결과
```

`piic` 한 번이면 **희석률 분모(증자전 발행주식총수)와 자금용도 항목별 금액**이 확정치로 나온다.
이수페타시스 케이스에서 `[확인필요]`로 남았던 항목들이 여기서 해소된다.
API 키는 프로젝트 루트 `.env` 의 `DART_API_KEY` (gitignore 처리).
