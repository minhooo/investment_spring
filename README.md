# 투자 이슈 케이스 스터디 아카이브

웹 대시보드: [투자 샘터](https://investment-spring.vercel.app) · [사례 탐색](https://investment-spring.vercel.app/#cases) · [배포·운영 가이드](docs/DEPLOYMENT.md)

> 주식시장에서 **특정 이슈(공시·이벤트)가 등장했을 때**, 과거 유사 사례를 30초 안에 찾아
> "이건 어떤 유형이고, 과거 같은 유형은 어떻게 끝났나"를 판단하기 위한 개인 아카이브.

핵심 질문 한 줄: **"이 이슈, 전에 본 적 있는데 그때 돈이 어떻게 움직였지?"**

---

## 1. 중심 가설 ★

> ### **종목에 돈이 몰려야 주가가 움직인다.**
> 이슈(유상증자·지수편입·수주)는 그 자체가 주제가 아니라 **돈을 부르는 계기**다.
> 따라서 케이스에서 물을 것은 "이슈가 좋은가 나쁜가"가 아니라
> **"돈이 얼마나 몰렸고, 누가 몰았고, 얼마나 머물렀는가"** 이다.

**실측 8건이 말하는 것** (→ [`framework/02_자금유입_가설.md`](framework/02_자금유입_가설.md))

| 지표 | 초과수익 방향과 부호 일치 (31개 국면 · 케이스 8건) |
|---|---|
| **회전율 (유동시총 대비)** | **77%** |
| **개인 순매수 (역방향)** | **74%** |
| 외국인 순매수 (정방향) | 58% — 케이스별 1/4~3/3으로 편차 큼 |
| 기관계 순매수 | 68% |
| 거래대금 **절대금액** | 61% — 방향 정보 없음 |

**회전율의 분모는 반드시 유동시가총액이다.** 총시총으로 나누면 최대주주·자사주·보호예수 물량이
분모에 들어가 회전율이 과소평가되고, 유통비율이 다른 종목끼리는 비교가 성립하지 않는다.
(유통비율: **LS마린솔루션 29.2%** ~ 알테오젠 79.6% — 2.7배 차이) 31개 국면 실측에서 정규화 회전율의 방향 일치율은 **77%**로, 절대 거래대금의 **61%**보다 높았다.

인적분할 가설 검증은 위 8건의 자금유입 통계와 별도 표본으로 관리한다. 1호는 [2020년 솔브레인홀딩스·솔브레인](cases/인적분할/2020-08_솔브레인홀딩스_솔브레인_036830.md)이다. 분할 평가가격 대비 방향과 첫 종가 이후 투자성과, 분할비율 가중 합산가치를 따로 비교한다.

→ 가설은 맞되 **지표를 바꿔야 한다.** 여기서 '돈'은 거래대금이 아니라 **순매수**다.
정확히는 **주가가 크게 오르는 국면은 외국인이 개인에게서 물량을 받아가는 국면**이다.
초과 +50%p 이상 국면 8개 중 6개가 개인 순매도 + 외국인 순매수 조합.
반대로 **에코프로머티리얼즈 유상증자는 세 국면 전부 개인 순매수 + 외국인 순매도 + 회전율 평균 이하**였고,
세 국면 전부 초과수익이 마이너스였다 — 가설이 양방향으로 작동한 첫 케이스다.

수급 원천은 **키움증권 `ka10059`** (개인 포함 · 금액 기준). 네이버는 외국인·기관만 수량으로 준다.

### 이슈유형별 하위 명제

- **유상증자**: 자금용도가 미래 이익을 만들면 나중에 돈이 돌아온다 (희석은 즉시, 회수는 나중)
- **지수편입**: 편입이 부르는 패시브 자금은 **수명이 하루**다. 그 이후를 끌 자금원이 있어야 한다
- 반대 명제(귀무가설): "이슈의 성격만으로 주가 방향을 알 수 있다"
- 1호 케이스: [이수페타시스(007660) · 2024-11](cases/유상증자/2024-11_이수페타시스_007660.md) · [대시보드](dist/007660_dashboard.html)
- 실측: D-day 이후 명목 **+259.8%**, KOSPI **+161.1%** → **초과 +98.7%p** (2026-09-04 기준)
  · 상대강도 RS는 2025-11 고점 **304** 에서 **138** 로 반납 중

## 2. 30초 사용법

새 이슈가 떴을 때:

1. `templates/QUICK_TRIAGE.md` — 4문항으로 1차 분류 (5분)
2. `framework/유상증자/11_분류체계.md` — 유형코드(A~G) 확정
3. `INDEX.md` — **같은 유형코드·같은 패턴태그**로 과거 사례 역검색
4. 볼 가치가 있으면 `templates/CASE_TEMPLATE.md`로 새 케이스 작성 + 대시보드 빌드
5. `INDEX.md` 한 줄 + `data/cases.csv` 한 행 추가 (이걸 빼먹으면 아카이브가 죽는다)

명령줄 검색 예시:

```bash
grep -rl "#고점증자" cases/
grep -rl "유형코드: G" cases/
```

### 통합 대시보드

새 페이지·메뉴 제작과 디자인 변경 기준은 [디자인 및 페이지 확장 가이드](design/DESIGN_GUIDE.md)를 참고한다. 루트 `AGENTS.md`는 AI가 디자인 작업 시 이 가이드를 먼저 읽고 같은 작업에서 문서도 갱신하도록 지정한다.

기본 진입점은 https://investment-spring.vercel.app 이며, 로컬에서는 `dist/index.html`을 연다. 홈에서 **사례 탐색**, **거시 인과지도**, [**지수 레이더**](https://investment-spring.vercel.app/index-radar.html)로 들어갈 수 있으며, 사례는 이슈·테마·패턴·키워드로 찾는다.

탐색 전용 분류는 `data/navigation.json`, 이름·검색 별칭은 `data/taxonomy.json`에서 관리한다. 원본 사례 정보는 계속 `data/cases.csv`와 `data/meta/`가 담당한다.

```bash
# 사례 대시보드와 통합 홈/거시 화면을 모두 다시 생성
python tools/build_all.py
```

### 지수 레이더

`지수 레이더`는 KOSPI 200 구성목록과 키움 유통시가총액 기반 참고 비중을 기준일·출처·품질 상태와 함께 보여준다. [History](https://investment-spring.vercel.app/index-radar-history.html)는 첫 리뷰인 `2026년 상반기 KOSPI 200 정기변경`의 편입 4종목을 한 페이지에서 비교하고 종목별 앵커로 깊게 본다. 화면·데이터 계약과 KRX 방법론 재현, 이력, 후보 신호 확장 원칙은 [INDEX_RADAR_SPEC.md](design/INDEX_RADAR_SPEC.md)에 있다. 현재 구성목록은 네이버 증권 보조 출처이고, 현재가·시가총액·유통주식수·유통비율은 키움증권 REST `ka10001`으로 보강한다. History 관측값은 키움 `ka10059`, 지수 비중·리밸런싱 수요는 증권사 추정으로 서로 구분한다. 이는 KRX 공식 비중·지수주식수 기반 비중을 대신하지 않는다.

```bash
# 구성목록/현재가/시가총액 스냅샷 갱신 → 검증 → 화면 생성
python tools/fetch_index_data.py --index kospi200 --as-of 2026-09-04
python tools/validate_index_data.py --index kospi200
python tools/build_index_radar.py
python tools/build_index_radar_history.py
```

`data/cases.csv`에 등록한 표준 사례는 기존의 상세 분류를 유지한다. 별도 검증 대시보드는 `data/meta/*.json`과 짝이 되는 `dist/<종목코드>_*.html`만 있으면 홈 사례 탐색에 자동 등록된다. 메타에 `portal_title`, `portal_summary`, `theme_ids`, `event_date`, `event_label`, `aliases`를 넣으면 카드 문구와 분류를 더 세밀하게 지정할 수 있다.

개별 사례 빌더를 실행하면 상세 화면 생성 뒤 포털도 자동으로 다시 빌드된다. 열린 포털은 `dist/portal-data.js`의 리비전을 3초마다 확인해 새 사례를 현재 검색·필터 상태에 반영한다. 이 기능이 들어가기 전에 열어 둔 포털은 한 번 새로고침해야 하며, 빌더를 거치지 않은 원본 파일 편집까지 감지하는 상시 파일 감시기는 아니다.

온라인 반영은 `python tools/deploy_dashboard.py`(윈도우에서는 `deploy_dashboard.bat` 더블클릭)로 전체 빌드·Vercel 운영 배포·고정 주소 검증까지 실행한다. 로컬 빌드만으로 웹사이트가 바뀌지는 않는다. 이후 사례 추가 작업은 이 배포와 검증까지 마쳐야 완료다. 자세한 설정과 복구 방법은 [배포 가이드](docs/DEPLOYMENT.md)에 정리한다.

## 4. 다른 이슈로 확장하는 법

무상증자 / CB·BW 발행 / 물적분할 / 자사주 소각 / 대규모 수주 / 감자 / 블록딜 등으로 넓힐 때:

1. `framework/<이슈유형>/` 아래에 **판단프레임 · 분류체계 · 스코어카드**를 만든다 (데이터수집은 필요할 때만)
2. `cases/<이슈유형>/`에 케이스를 쌓는다
3. `INDEX.md`와 `data/cases.csv`는 이슈유형과 무관하게 **하나만** 유지한다 — 색인이 쪼개지면 교차 검색이 안 된다

## 5. 주의
